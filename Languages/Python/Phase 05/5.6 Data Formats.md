# 5.6 Data Formats

## Overview

Programs exchange data with other programs and store it between runs, so they need agreed formats. This module covers four: JSON, the standard format for web APIs; CSV, the standard format for tables and spreadsheets; TOML, a common format for configuration; and `pickle`, Python's own serialization format, which comes with serious security warnings.

## JSON

JSON (JavaScript Object Notation) is a text format for structured data. The `json` module converts between JSON text and Python objects.

| JSON | Python |
| --- | --- |
| object | `dict` |
| array | `list` |
| string | `str` |
| number without a fraction | `int` |
| number with a fraction | `float` |
| `true` and `false` | `True` and `False` |
| `null` | `None` |

### Strings and Files

```python
import json

data = {"name": "Amina", "scores": [90, 85], "active": True, "address": None}

text = json.dumps(data)                  # Python object to JSON string
print(text)
# {"name": "Amina", "scores": [90, 85], "active": true, "address": null}

restored = json.loads(text)              # JSON string to Python object
print(restored["scores"])                # [90, 85]

with open("data.json", "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2)         # write to a file

with open("data.json", encoding="utf-8") as f:
    loaded = json.load(f)                # read from a file
```

The `s` in `dumps` and `loads` stands for string. `dump` and `load` work with file objects.

### Useful Options

```python
json.dumps(data, indent=2)                    # pretty printing
json.dumps(data, sort_keys=True)              # stable key order
json.dumps({"city": "Dhaka"}, ensure_ascii=False)   # keep non-ASCII characters readable
json.dumps(data, separators=(",", ":"))       # most compact output
```

### What JSON Cannot Represent

- Dictionary keys become strings: `{1: "a"}` is written as `{"1": "a"}`.
- Tuples become arrays and come back as lists.
- `Decimal`, `datetime`, `UUID`, `set`, and your own objects raise `TypeError`. Supply a `default` function that converts them.
- Floats lose exactness. For money, read numbers as `Decimal` with `json.loads(text, parse_float=Decimal)`.

```python
import json
from datetime import datetime

def to_jsonable(value):
    if isinstance(value, datetime):
        return value.isoformat()
    raise TypeError(f"cannot serialize {type(value).__name__}")

print(json.dumps({"at": datetime(2026, 3, 1, 9, 30)}, default=to_jsonable))
```

### Invalid JSON

```python
try:
    json.loads("{'name': 'Amina'}")        # single quotes are not valid JSON
except json.JSONDecodeError as exc:
    print(exc)
    # Expecting property name enclosed in double quotes: line 1 column 2 (char 1)
```

`JSONDecodeError` is a subclass of `ValueError`.

## CSV

CSV (comma-separated values) stores rows of a table as lines of text. The `csv` module handles quoting and commas inside values for you, so do not split lines on commas yourself.

Open CSV files with `newline=""` and an explicit encoding.

```python
import csv

with open("people.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerow(["name", "age"])
    writer.writerow(["Amina", 31])
    writer.writerows([["Bilal", 25], ["Chen, Li", 40]])
    # the comma is quoted automatically

with open("people.csv", newline="", encoding="utf-8") as f:
    reader = csv.reader(f)
    for row in reader:
        print(row)                 # ['name', 'age'], ['Amina', '31'], ...
```

Every value read from a CSV file is a string. Convert to numbers explicitly.

`DictReader` and `DictWriter` use the header row to give each row as a dictionary, which is clearer and survives column reordering.

```python
with open("people.csv", newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        print(row["name"], int(row["age"]))

with open("out.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["name", "age"])
    writer.writeheader()
    writer.writerow({"name": "Dara", "age": 29})
```

Other delimiters, such as semicolons or tabs, are set with `delimiter=";"` or `delimiter="\t"`.

## TOML

TOML is a configuration format that is readable by humans and has clear types. It is the format of `pyproject.toml`. Python 3.11 and newer can read it with the built-in `tomllib`.

```toml
title = "Orders service"

[server]
host = "0.0.0.0"
port = 8000
debug = false

[database]
url = "postgresql://localhost/orders"
pool_size = 10
```

```python
import tomllib

with open("settings.toml", "rb") as f:            # note: binary mode
    settings = tomllib.load(f)

print(settings["server"]["port"])                 # 8000 (an int)
print(settings["database"]["pool_size"])          # 10

config = tomllib.loads('name = "demo"')           # parse from a string
```

`tomllib` can only read TOML. To write it you need a third-party library such as `tomli-w`. Invalid input raises `tomllib.TOMLDecodeError`. Tables become dictionaries, and TOML dates become `datetime` objects.

## pickle

`pickle` serializes almost any Python object into bytes and restores it later.

```python
import pickle

data = {"scores": [90, 85], "tags": {"a", "b"}}

with open("data.pkl", "wb") as f:
    pickle.dump(data, f)

with open("data.pkl", "rb") as f:
    restored = pickle.load(f)
```

It is convenient, but it comes with serious limits.

- Security risk: unpickling is not just reading data. A pickle can contain instructions that run arbitrary code when it is loaded. Loading a pickle from an untrusted or unauthenticated source can give an attacker full control of your program. Never unpickle data received from the network, from users, or from any file someone else could modify.
- It is specific to Python and is not readable by humans or other languages.
- It depends on your code. A pickle of a class instance may fail to load after the class is renamed, moved, or changed, and it may not load across Python versions.

For data that crosses a trust boundary, or that other systems or future code versions must read, use JSON or another explicit format. Reserve `pickle` for short-lived data that only your own program, running trusted code, writes and reads, such as a local cache.

## Choosing a Format

| Need | Use |
| --- | --- |
| API request and response bodies, general structured data | JSON |
| Tables, spreadsheets, bulk import and export | CSV |
| Human-edited configuration | TOML |
| Temporary cache of Python objects, fully trusted | `pickle` |

## Basic Examples

```python
import csv
import json

# Convert a CSV file to JSON
with open("people.csv", newline="", encoding="utf-8") as f:
    rows = list(csv.DictReader(f))

with open("people.json", "w", encoding="utf-8") as f:
    json.dump(rows, f, indent=2, ensure_ascii=False)

# Pretty print a JSON string
raw = '{"b": 2, "a": [1, 2, 3]}'
print(json.dumps(json.loads(raw), indent=2, sort_keys=True))
```

## Backend Industry Example

Four tasks that appear in nearly every service: producing JSON that contains money and dates, reading money from JSON without losing precision, loading TOML settings with defaults, and importing a CSV file while collecting every row-level error.

```python
import csv
import json
import tempfile
import tomllib
from datetime import datetime, timezone
from decimal import Decimal, InvalidOperation
from pathlib import Path
from uuid import UUID, uuid4


# 1. JSON with types the json module does not know
def json_default(value: object) -> object:
    if isinstance(value, Decimal):
        return str(value)                # a string keeps the exact digits
    if isinstance(value, datetime):
        return value.isoformat()
    if isinstance(value, UUID):
        return str(value)
    if isinstance(value, set):
        return sorted(value)
    raise TypeError(f"cannot serialize {type(value).__name__}")


def to_json(payload: dict) -> str:
    return json.dumps(
        payload, default=json_default, separators=(",", ":"), sort_keys=True
    )


response = {
    "id": uuid4(),
    "total": Decimal("64.49"),
    "created": datetime(2026, 3, 1, 9, 30, tzinfo=timezone.utc),
    "tags": {"gift", "priority"},
}
print(to_json(response)[:60] + "...")

# 2. Reading numbers as Decimal so that money stays exact
incoming = json.loads('{"price": 19.99, "quantity": 3}', parse_float=Decimal)
print(incoming["price"] * incoming["quantity"])         # 59.97


# 3. TOML settings merged over defaults
DEFAULT_SETTINGS = {"host": "127.0.0.1", "port": 8000, "debug": False}


def load_settings(path: Path) -> dict:
    """Read the [server] table of a TOML file and apply it over the defaults."""
    try:
        with path.open("rb") as f:
            file_settings = tomllib.load(f).get("server", {})
    except FileNotFoundError:
        file_settings = {}
    except tomllib.TOMLDecodeError as exc:
        raise ValueError(f"invalid settings file {path}: {exc}") from exc
    return DEFAULT_SETTINGS | file_settings


# 4. CSV import that reports every bad row instead of stopping at the first
REQUIRED_COLUMNS = {"order_id", "email", "amount"}


def import_orders(path: Path) -> tuple[list[dict], list[str]]:
    """Return (valid_orders, error_messages) for a CSV file of orders."""
    orders: list[dict] = []
    errors: list[str] = []
    with path.open(newline="", encoding="utf-8") as f:
        reader = csv.DictReader(f)
        missing = REQUIRED_COLUMNS - set(reader.fieldnames or [])
        if missing:
            raise ValueError(f"missing columns: {sorted(missing)}")
        for line_number, row in enumerate(reader, start=2):   # line 1 is the header
            order_id = row["order_id"].strip()
            email = row["email"].strip().lower()
            if not order_id or "@" not in email:
                errors.append(
                    f"line {line_number}: order_id and a valid email are required"
                )
                continue
            try:
                amount = Decimal(row["amount"])
            except InvalidOperation:
                errors.append(f"line {line_number}: invalid amount {row['amount']!r}")
                continue
            orders.append({"order_id": order_id, "email": email, "amount": amount})
    return orders, errors


with tempfile.TemporaryDirectory() as workdir:
    folder = Path(workdir)

    (folder / "settings.toml").write_text('[server]\nport = 9000\n', encoding="utf-8")
    print(load_settings(folder / "settings.toml"))     # port overridden, rest defaults
    print(load_settings(folder / "missing.toml"))      # all defaults

    (folder / "orders.csv").write_text(
        "order_id,email,amount\n"
        "A-1,Amina@Example.com,120.50\n"
        "A-2,not-an-email,10\n"
        "A-3,chen@example.com,abc\n"
        "A-4,dara@example.com,35.00\n",
        encoding="utf-8",
    )
    good, problems = import_orders(folder / "orders.csv")
    print(len(good), "valid orders")                   # 2 valid orders
    for problem in problems:
        print(problem)
```

The `default` function gives one central place that decides how each unusual type appears in JSON. Money is written as a string and read back as a `Decimal`, so no cent is ever lost to binary floating point. The CSV importer validates each row, records what is wrong with it and moves on, so one malformed line does not force the user to fix a file one error at a time.

## Common Mistakes

- Trying to serialize `Decimal`, `datetime`, or `set` values without a `default` function.
- Storing money as a JSON float.
- Splitting CSV lines on commas manually instead of using the `csv` module.
- Forgetting `newline=""` when opening CSV files, which can produce blank lines on Windows.
- Opening TOML files in text mode. `tomllib.load` needs a binary file.
- Forgetting that all CSV values are strings.
- Unpickling data from any source that is not fully trusted.
- Using `pickle` as a long-term storage or exchange format.

## Summary

Use JSON for structured data and APIs, giving unusual types a `default` conversion and reading money as `Decimal`. Use `csv` with `newline=""` for tables, preferring `DictReader` and `DictWriter`. Use `tomllib` for reading configuration, in binary mode. Treat `pickle` as a Python-only, code-executing format that must never touch untrusted data.
