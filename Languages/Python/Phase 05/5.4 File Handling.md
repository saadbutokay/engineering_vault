# 5.4 File Handling

## Overview

Programs read configuration, process uploads, write reports, and store data in files. Python's built-in `open()` function is the foundation for all of it. This module covers modes, encodings, reading and writing text and binary data, buffering, and how to process large files without running out of memory.

## Opening Files

```python
with open("notes.txt", "r", encoding="utf-8") as f:
    text = f.read()
```

Always use `with`, so the file is closed even if an error occurs. Always pass `encoding="utf-8"` for text files. Without it, Python uses an encoding that depends on the operating system and its settings, and the same program can read or write different bytes on different machines.

## Modes

| Mode | Meaning | If the file exists | If it does not exist |
| --- | --- | --- | --- |
| `"r"` | read text (default) | read it | `FileNotFoundError` |
| `"w"` | write text | erase it first | create it |
| `"a"` | append text | add to the end | create it |
| `"x"` | create exclusively | `FileExistsError` | create it |
| `"r+"` | read and write | keep content, write at the start | `FileNotFoundError` |

Add `b` for binary mode (`"rb"`, `"wb"`, `"ab"`). Text mode (the default, `"t"`) works with `str`. Binary mode works with `bytes` and does no decoding or newline translation.

Opening with `"w"` destroys the existing content immediately, even if you never write anything. Use `"x"` when overwriting would be a bug.

## Reading Text

```python
with open("data.txt", encoding="utf-8") as f:
    content = f.read()            # the whole file as one string

with open("data.txt", encoding="utf-8") as f:
    first_line = f.readline()     # one line, including the trailing newline

with open("data.txt", encoding="utf-8") as f:
    lines = f.readlines()         # a list of all lines

with open("data.txt", encoding="utf-8") as f:
    for line in f:                # one line at a time, memory friendly
        print(line.rstrip("\n"))
```

`read()` and `readlines()` load the entire file into memory. For anything that might be large, iterate over the file object instead.

## Writing Text

```python
with open("report.txt", "w", encoding="utf-8") as f:
    f.write("Title\n")                     # write() does not add a newline
    f.write("Line two\n")
    f.writelines(["a\n", "b\n"])           # writelines() does not add newlines either
    print("printed line", file=f)          # print adds the newline for you
```

Appending:

```python
with open("report.txt", "a", encoding="utf-8") as f:
    f.write("one more line\n")
```

In text mode, `\n` is translated to the platform's line ending when writing, and any line ending is translated to `\n` when reading. When working with the `csv` module, open files with `newline=""` so it can manage line endings itself.

## Binary Files

Use binary mode for images, archives, PDFs, and any data that is not text.

```python
with open("photo.jpg", "rb") as f:
    data = f.read()          # bytes
print(len(data), data[:4])

with open("copy.jpg", "wb") as f:
    f.write(data)
```

## Processing Large Files

Never read a very large file into memory at once. Two patterns avoid it.

Iterate line by line for text:

```python
line_count = 0
with open("huge.log", encoding="utf-8") as f:
    for line in f:
        line_count += 1
```

Read fixed-size chunks for binary data or data without lines:

```python
CHUNK_SIZE = 64 * 1024

with open("big.bin", "rb") as source, open("copy.bin", "wb") as target:
    while chunk := source.read(CHUNK_SIZE):
        target.write(chunk)
```

`read(size)` returns an empty bytes object at the end of the file, which is falsy, so the loop stops.

## Buffering

Python does not send every `write` straight to the disk. It collects data in a buffer, typically around 8 KB, and writes it in larger pieces.

- `f.flush()` pushes the buffer to the operating system.
- Closing the file flushes automatically, which is another reason to use `with`.
- `os.fsync(f.fileno())` after `flush()` asks the operating system to write the data to the physical disk. Use it when losing the data on a crash or power cut is unacceptable.
- `open(path, "w", buffering=1)` selects line buffering in text mode, which can be useful for a log file you follow live.

## File Position

```python
with open("data.txt", "r+", encoding="utf-8") as f:
    f.read(5)
    print(f.tell())        # current position
    f.seek(0)              # back to the beginning
    print(f.read(5))
```

In text mode, only seek to `0` or to a value previously returned by `tell()`.

## Errors to Expect

| Exception | Typical cause |
| --- | --- |
| `FileNotFoundError` | wrong path, or the folder does not exist |
| `PermissionError` | no permission to read or write |
| `IsADirectoryError` | the path is a folder |
| `FileExistsError` | mode `"x"` and the file already exists |
| `UnicodeDecodeError` | the file is not in the encoding you specified |
| `OSError` | other system problems such as a full disk |

## Basic Examples

```python
# Write then read
with open("shopping.txt", "w", encoding="utf-8") as f:
    f.write("milk\n")
    f.write("bread\n")
    f.write("eggs\n")

with open("shopping.txt", encoding="utf-8") as f:
    items = [line.strip() for line in f]
print(items)                      # ['milk', 'bread', 'eggs']

# Count lines containing a word
with open("shopping.txt", encoding="utf-8") as f:
    matches = sum(1 for line in f if "e" in line)
print(matches)

# Append a record
with open("shopping.txt", "a", encoding="utf-8") as f:
    f.write("rice\n")
```

## Backend Industry Example

Three tasks that real services perform: replacing a file so that a reader never sees a half-written version, scanning a large log file in constant memory, and computing a checksum of an uploaded file.

```python
import hashlib
import os
import tempfile


def atomic_write_text(path: str, text: str, encoding: str = "utf-8") -> None:
    """Write a file so readers see either the old content or the new, never half.

    The data is written to a temporary file in the same directory and then
    swapped into place with os.replace, which is atomic on the same filesystem.
    """
    directory = os.path.dirname(os.path.abspath(path))
    fd, temp_path = tempfile.mkstemp(dir=directory, suffix=".tmp")
    try:
        with os.fdopen(fd, "w", encoding=encoding) as temp_file:
            temp_file.write(text)
            temp_file.flush()
            os.fsync(temp_file.fileno())      # data is on disk before the swap
        os.replace(temp_path, path)
    except BaseException:
        if os.path.exists(temp_path):
            os.remove(temp_path)
        raise


def count_log_levels(path: str) -> dict[str, int]:
    """Count ERROR and WARNING lines in a log file of any size."""
    counts = {"ERROR": 0, "WARNING": 0}
    with open(path, encoding="utf-8", errors="replace") as log_file:
        for line in log_file:                 # one line in memory at a time
            for level in counts:
                if f" {level} " in line:
                    counts[level] += 1
    return counts


def sha256_of_file(path: str, chunk_size: int = 1024 * 1024) -> str:
    """Return the SHA-256 hex digest of a file, reading it in chunks."""
    digest = hashlib.sha256()
    with open(path, "rb") as file:
        while chunk := file.read(chunk_size):
            digest.update(chunk)
    return digest.hexdigest()


with tempfile.TemporaryDirectory() as workdir:
    config_path = os.path.join(workdir, "settings.json")
    atomic_write_text(config_path, '{"debug": false}\n')
    atomic_write_text(config_path, '{"debug": true}\n')    # replaces safely
    print(open(config_path, encoding="utf-8").read().strip())    # {"debug": true}

    log_path = os.path.join(workdir, "app.log")
    atomic_write_text(
        log_path,
        "2026-03-01 10:00:01 INFO started\n"
        "2026-03-01 10:00:02 WARNING slow query\n"
        "2026-03-01 10:00:03 ERROR payment failed\n"
        "2026-03-01 10:00:04 ERROR timeout\n",
    )
    print(count_log_levels(log_path))             # {'ERROR': 2, 'WARNING': 1}
    print(sha256_of_file(log_path)[:16])          # first 16 characters of the checksum
```

Writing a configuration file directly with `open(path, "w")` is dangerous in a live service: the file is empty from the moment it is opened until the write finishes, and a crash in between leaves it empty or truncated. The temporary file and `os.replace` pattern removes that risk. The log scanner uses constant memory, so it handles a 50 GB log as well as a 5 KB one, and `errors="replace"` stops a single corrupt byte from crashing the scan.

## Common Mistakes

- Opening a file in `"w"` mode and erasing its content by accident.
- Omitting `encoding="utf-8"` and getting different results on different machines.
- Reading a huge file with `read()` and running out of memory.
- Forgetting that `write()` and `writelines()` do not add newlines.
- Not closing files. Use `with`.
- Opening a text file in binary mode, or the reverse, and then mixing `str` and `bytes`.
- Writing configuration or state in place, where a crash can leave a half-written file.
- Assuming a relative path refers to the folder of the script instead of the current working directory.

## Summary

Open files with `with open(path, mode, encoding="utf-8")`. Choose the mode deliberately: `"w"` erases, `"a"` appends, `"x"` refuses to overwrite, and `b` means bytes. Read large files by iterating over lines or over fixed-size chunks. Remember that writes are buffered, flush and `fsync` when durability matters, and write important files atomically by replacing them from a temporary file.
