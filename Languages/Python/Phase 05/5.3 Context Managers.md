# 5.3 Context Managers

## Overview

A context manager guarantees that setup and cleanup happen as a pair. You use one with the `with` statement. The classic example is a file that must be closed, but the same idea applies to database transactions, locks, temporary directories, timers, and network connections. It is the safe, readable replacement for `try` and `finally`.

## The with Statement

```python
with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("hello")
# the file is closed here, even if write() raised an exception
```

This is equivalent to:

```python
f = open("notes.txt", "w", encoding="utf-8")
try:
    f.write("hello")
finally:
    f.close()
```

The `with` form is shorter and cannot forget the cleanup.

Several context managers can be combined in one statement by separating them with commas. Python 3.10 and newer also allow parentheses, which keeps long lines readable:

```python
with (
    open("in.txt", encoding="utf-8") as source,
    open("out.txt", "w", encoding="utf-8") as target,
):
    target.write(source.read())
```

They are entered left to right and exited right to left.

## The Protocol: `__enter__` and `__exit__`

An object is a context manager if it defines two methods.

- `__enter__(self)` runs at the start of the `with` block. Its return value is bound to the name after `as`.
- `__exit__(self, exc_type, exc, traceback)` runs at the end, whether the block finished normally or raised. The three arguments describe the exception, or are all `None` when there was none. If `__exit__` returns `True`, the exception is suppressed. Otherwise it propagates.

```python
import time


class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self

    def __exit__(self, exc_type, exc, traceback):
        self.elapsed = time.perf_counter() - self.start
        print(f"took {self.elapsed:.4f}s")
        return False          # never suppress exceptions


with Timer() as timer:
    total = sum(range(1_000_000))

print(timer.elapsed)
```

## contextlib.contextmanager

Writing a class for every context manager is verbose. The `contextmanager` decorator turns a generator function with a single `yield` into one. Code before `yield` is the setup, the yielded value is what `as` receives, and code after `yield` is the cleanup.

```python
from contextlib import contextmanager
import time


@contextmanager
def timer(label):
    start = time.perf_counter()
    try:
        yield
    finally:
        print(f"{label}: {time.perf_counter() - start:.4f}s")


with timer("sum"):
    sum(range(1_000_000))
```

If the body of the `with` raises an exception, it is raised again at the `yield` line inside the generator. Wrapping `yield` in `try/finally` makes the cleanup run in every case. Without the `try`, cleanup is skipped when the body fails.

## ExitStack

`ExitStack` manages a number of context managers that is not known in advance, and it also registers arbitrary cleanup callbacks.

```python
from contextlib import ExitStack

paths = ["a.txt", "b.txt", "c.txt"]

with ExitStack() as stack:
    files = [stack.enter_context(open(path, encoding="utf-8")) for path in paths]
    for f in files:
        print(f.readline())
# all three files are closed here, in reverse order

with ExitStack() as stack:
    stack.callback(print, "cleanup finished")
    print("working")
```

## suppress

`suppress` ignores the listed exceptions inside a block. It reads better than an empty `except`.

```python
import os
from contextlib import suppress

with suppress(FileNotFoundError):
    os.remove("old-cache.tmp")
```

Use it only where ignoring the error is truly the correct behaviour.

## Other Useful Tools

```python
from contextlib import closing, nullcontext, redirect_stdout
import io

buffer = io.StringIO()
with redirect_stdout(buffer):
    print("captured")
print(buffer.getvalue())               # captured

use_lock = False
with (open("x.txt") if use_lock else nullcontext()):
    pass
    # nullcontext does nothing, useful for optional contexts
```

`closing(obj)` calls `obj.close()` on exit, for objects that have `close` but are not context managers themselves.

## Basic Examples

```python
with open("greeting.txt", "w", encoding="utf-8") as f:
    f.write("Hello\nWorld\n")

with open("greeting.txt", encoding="utf-8") as f:
    for line in f:
        print(line.strip())

print(f.closed)    # True: the file object still exists but is closed
```

## Backend Industry Example

A database transaction as a context manager, so every use commits on success and rolls back on any error, and a timing context manager that writes to the log. The example uses `sqlite3` from the standard library.

```python
import logging
import sqlite3
import time
from collections.abc import Iterator
from contextlib import contextmanager

logger = logging.getLogger(__name__)


@contextmanager
def transaction(conn: sqlite3.Connection) -> Iterator[sqlite3.Connection]:
    """Commit if the block succeeds, roll back if it raises."""
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise


@contextmanager
def timed(label: str) -> Iterator[None]:
    """Log how long a block takes, even if it fails."""
    start = time.perf_counter()
    try:
        yield
    finally:
        logger.info("%s took %.1f ms", label, (time.perf_counter() - start) * 1000)


def transfer(conn: sqlite3.Connection, source: int, target: int, amount: int) -> None:
    """Move money between two accounts atomically."""
    with timed("transfer"), transaction(conn):
        conn.execute(
            "UPDATE accounts SET balance = balance - ? WHERE id = ?", (amount, source)
        )
        conn.execute(
            "UPDATE accounts SET balance = balance + ? WHERE id = ?", (amount, target)
        )
        balance = conn.execute(
            "SELECT balance FROM accounts WHERE id = ?", (source,)
        ).fetchone()[0]
        if balance < 0:
            raise ValueError("insufficient funds")   # triggers the rollback


connection = sqlite3.connect(":memory:")
connection.execute("CREATE TABLE accounts (id INTEGER PRIMARY KEY, balance INTEGER)")
connection.executemany("INSERT INTO accounts VALUES (?, ?)", [(1, 100), (2, 50)])
connection.commit()

transfer(connection, 1, 2, 30)
print(connection.execute("SELECT id, balance FROM accounts").fetchall())
# [(1, 70), (2, 80)]

try:
    transfer(connection, 1, 2, 500)
except ValueError as exc:
    print("rejected:", exc)

print(connection.execute("SELECT id, balance FROM accounts").fetchall())
# [(1, 70), (2, 80)]   the failed transfer changed nothing
connection.close()
```

The two updates form one unit of work. When the check fails, `rollback` undoes the first update, so money is never lost or created. The `transaction` context manager is written once and every database operation in the application can use it, instead of repeating `try`, `commit`, and `rollback` each time. The SQL uses `?` placeholders instead of string formatting, which prevents SQL injection.

## Common Mistakes

- Opening files without `with` and forgetting to close them.
- Forgetting the `try/finally` around `yield` in a `@contextmanager` function, so the cleanup does not run on errors.
- Writing a `@contextmanager` generator that yields more than once.
- Returning `True` from `__exit__` accidentally, which silently swallows every exception.
- Using the resource after the `with` block, when it has already been cleaned up.
- Using `suppress` to hide errors that should be investigated.

## Summary

A context manager pairs setup with guaranteed cleanup and is used with `with`. Classes implement `__enter__` and `__exit__`, and `@contextlib.contextmanager` builds one from a generator with `yield`. Use `ExitStack` for a variable number of resources and `suppress` for deliberately ignored errors. Wrap transactions, locks, files, and timers in context managers so cleanup never depends on remembering to write it.
