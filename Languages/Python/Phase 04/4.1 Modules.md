# 4.1 Modules

## Overview

A module is a single Python file that holds code you can reuse from other files. Modules let you split a program into small, named parts, and they are also how you use the standard library and third-party packages. Every `.py` file you write is already a module.

## What a Module Is

If a file is named `mathutils.py`, then its module name is `mathutils`. Another file in the same folder can use it with `import`.

```python
# mathutils.py
"""Small math helpers."""

PI = 3.14159


def circle_area(radius):
    return PI * radius ** 2


def is_even(number):
    return number % 2 == 0
```

```python
# app.py
import mathutils

print(mathutils.circle_area(3))    # 28.27431
print(mathutils.is_even(4))        # True
print(mathutils.PI)                # 3.14159
```

When Python imports a module it runs the file from top to bottom once, and the names it defines (`PI`, `circle_area`, `is_even`) become attributes of a module object.

## Import Forms

```python
import math                          # use as math.sqrt(16)
from math import sqrt, pi            # use as sqrt(16) and pi
import datetime as dt                # alias: dt.date.today()
from decimal import Decimal as D     # alias for one name
from math import *                   # imports every public name: avoid
```

Comparison:

| Form | Advantage | Drawback |
| --- | --- | --- |
| `import math` | Shows where each name comes from (`math.sqrt`), no name collisions | slightly longer to type |
| `from math import sqrt` | Short names | The origin of `sqrt` is not visible at the use site, and it can collide with your own names |
| `import x as y` | Shorten long names or follow conventions | Unusual aliases confuse readers |
| `from x import *` | None worth having | Pollutes your namespace and hides where names come from |

Follow established aliases when they exist, for example `import numpy as np` and `import pandas as pd`. Do not invent surprising ones.

## Inspecting a Module

```python
import math

print(math.__name__)       # math
print(math.__doc__)        # first line of its docstring
print(dir(math))           # list of all names it defines
help(math.sqrt)            # documentation for one function

import mathutils
print(mathutils.__file__)  # path of the file that was imported
```

`__file__` is the quickest way to answer "which file did Python actually import?".

## Modules Run Once on Import

The code at the top level of a module executes the first time it is imported. Later imports reuse the already loaded module.

```python
# noisy.py
print("loading noisy")
VALUE = 42
```

```python
import noisy      # prints: loading noisy
import noisy      # prints nothing, the module is already loaded
from noisy import VALUE
```

Because of this, module top-level code should define things (constants, functions, classes) and not do work such as opening connections or calling networks.

## `__name__ == "__main__"`

Every module has a `__name__` attribute. When a file is run directly, Python sets its `__name__` to `"__main__"`. When it is imported, `__name__` is the module's name. This lets one file serve both as a reusable module and as a program.

```python
# greeter.py
def greet(name):
    return f"Hello, {name}!"


if __name__ == "__main__":
    print(greet("Amina"))
```

```bash
python greeter.py        # prints Hello, Amina!
```

```python
import greeter           # prints nothing, the guarded block is skipped
```

Without the guard, the `print` would run every time another file imported `greeter`.

## Module Docstrings

A string at the very top of the file, before any code, documents the module. It appears in `help()` and in editors, and it should explain what the module is for.

```python
"""Pricing rules for the orders service.

Contains discount and tax calculations. All amounts are Decimal values.
"""
```

## Basic Examples

```python
# shapes.py
"""Area calculations for simple shapes."""

import math


def circle_area(radius):
    return math.pi * radius ** 2


def rectangle_area(width, height):
    return width * height


if __name__ == "__main__":
    print(circle_area(1))
    print(rectangle_area(3, 4))
```

```python
# report.py
from shapes import circle_area, rectangle_area
import shapes as sh

print(round(circle_area(2), 2))    # 12.57
print(rectangle_area(3, 4))        # 12
print(sh.rectangle_area(2, 5))     # 10
```

## Backend Industry Example

A module that other code can import and that also works as a small command-line tool for quick checks. The business logic lives in functions, argument handling lives in `main`, and the guard keeps import free of side effects.

```python
# pricing.py
"""Pricing rules for the orders service.

Import apply_discount from other code, or run the module directly for a
quick calculation:

    python pricing.py 120.00 0.10
"""

import sys
from decimal import ROUND_HALF_UP, Decimal

MAX_DISCOUNT_RATE = Decimal("0.30")
CENTS = Decimal("0.01")


def apply_discount(subtotal: Decimal, discount_rate: Decimal) -> Decimal:
    """Return the subtotal after a percentage discount, rounded to cents."""
    if subtotal < 0:
        raise ValueError("subtotal must not be negative")
    if not Decimal("0") <= discount_rate <= MAX_DISCOUNT_RATE:
        raise ValueError(f"discount_rate must be between 0 and {MAX_DISCOUNT_RATE}")
    discounted = subtotal * (Decimal("1") - discount_rate)
    return discounted.quantize(CENTS, rounding=ROUND_HALF_UP)


def main(argv: list[str]) -> int:
    """Command-line entry point. Returns a process exit code."""
    if len(argv) != 2:
        print("usage: python pricing.py SUBTOTAL DISCOUNT_RATE", file=sys.stderr)
        return 2
    try:
        print(apply_discount(Decimal(argv[0]), Decimal(argv[1])))
    except (ArithmeticError, ValueError) as exc:
        print(f"error: {exc}", file=sys.stderr)
        return 1
    return 0


if __name__ == "__main__":
    raise SystemExit(main(sys.argv[1:]))
```

```bash
python pricing.py 120.00 0.10      # prints 108.00
python pricing.py 120.00 0.90      # error: discount_rate must be between 0 and 0.30
```

Another module in the same project reuses the logic with a normal import:

```python
# invoice.py
from decimal import Decimal

from pricing import apply_discount

line_total = apply_discount(Decimal("250.00"), Decimal("0.15"))
print(f"Invoice line: {line_total}")    # Invoice line: 212.50
```

`main` takes `argv` as a parameter and returns an exit code, so it can be tested without starting a process. `SystemExit` turns the returned number into the process exit status.

## Common Mistakes

- Naming your file the same as a standard library or installed module, such as `random.py`, `json.py`, `email.py`, or `requests.py`. Python imports your file instead of the real one, and the error messages are confusing. If `import random` behaves strangely, print `random.__file__`.
- Using `from module import *`.
- Putting code that connects to databases or networks at the top level of a module.
- Forgetting the `__main__` guard so that importing a file runs its demo code.
- Running a script from a different directory than the one containing the modules it imports.
- Naming modules with hyphens or spaces. Module names must be valid identifiers, so use `snake_case`.

## Summary

A module is a `.py` file, and `import` makes its names available to other files. Prefer `import module` or explicit `from module import name`, and avoid wildcard imports. A module runs once at first import, so keep its top level free of side effects. Use the `__name__ == "__main__"` guard to make a file both importable and runnable, and write a docstring at the top of every module.
