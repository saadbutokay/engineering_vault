# 2.3 Dictionaries

## Overview

A dictionary (`dict`) stores key and value pairs and finds a value from its key very quickly. It is the structure behind JSON objects, configuration, caches, lookups by ID, and counting. If you can write a clear question such as "what is the email of user 17?", a dictionary can usually answer it.

## Creation

```python
empty = {}
user = {"name": "Amina", "age": 31}
from_keywords = dict(name="Amina", age=31)
from_pairs = dict([("name", "Amina"), ("age", 31)])
defaults = dict.fromkeys(["a", "b", "c"], 0)    # {'a': 0, 'b': 0, 'c': 0}
```

Keys must be hashable: strings, numbers, and tuples of hashable items are fine, while lists, dictionaries, and sets are not. Values can be anything.

## Access, Add, Change, Delete

```python
user = {"name": "Amina", "age": 31}

print(user["name"])               # Amina
print(user["email"])              # KeyError: 'email'
print(user.get("email"))          # None
print(user.get("email", "n/a"))   # n/a

user["email"] = "amina@example.com"   # add
user["age"] = 32                      # change
del user["age"]                       # delete
removed = user.pop("email", None)     # remove and return, with a default
print("name" in user)                 # True: `in` checks keys
```

## Useful Methods

```python
d = {"a": 1, "b": 2}
d.update({"b": 20, "c": 3})     # {'a': 1, 'b': 20, 'c': 3}
print(len(d))                   # 3
print(d.keys())                 # dict_keys(['a', 'b', 'c'])
print(d.values())               # dict_values([1, 20, 3])
print(d.items())                # dict_items([('a', 1), ('b', 20), ('c', 3)])
last = d.popitem()              # removes and returns the last inserted pair
d.clear()
```

`keys()`, `values()`, and `items()` return live views of the dictionary, not copies.

## Iteration

```python
prices = {"pen": 2, "notebook": 5, "bag": 40}

for key in prices:                   # iterates over keys
    print(key)

for name, price in prices.items():   # keys and values together
    print(f"{name}: {price}")

total = sum(prices.values())
```

Do not add or remove keys while looping over a dictionary. Python raises `RuntimeError: dictionary changed size during iteration`. Loop over `list(d)` or build a new dictionary instead.

## get versus setdefault

`get` reads without changing the dictionary. `setdefault(key, default)` returns the existing value, and if the key is missing it first stores the default. It is useful for grouping.

```python
groups = {}
for word in ["apple", "avocado", "banana", "blueberry", "cherry"]:
    groups.setdefault(word[0], []).append(word)
print(groups)
# {'a': ['apple', 'avocado'], 'b': ['banana', 'blueberry'], 'c': ['cherry']}
```

## Merging

```python
defaults = {"timeout": 5, "retries": 3}
overrides = {"retries": 5}

merged = defaults | overrides            # {'timeout': 5, 'retries': 5}
merged2 = {**defaults, **overrides}      # same result, older syntax
defaults |= overrides                    # update in place
```

When both sides have the same key, the right side wins. Merging with `|` is available in Python 3.9 and newer.

## Dictionary Comprehensions

```python
squares = {n: n * n for n in range(5)}           # {0: 0, 1: 1, 2: 4, 3: 9, 4: 16}
expensive = {k: v for k, v in prices.items() if v > 3}
inverted = {v: k for k, v in prices.items()}     # values must be unique and hashable
```

## Insertion Order

Dictionaries remember the order in which keys were first inserted. This is guaranteed in current Python. Updating an existing key does not move it. Two dictionaries with the same pairs are equal regardless of order.

## Hashing Basics

A dictionary is built on a hash table. Python computes a number, the hash, from the key, and uses it to jump almost directly to where the value is stored. This is why lookups stay fast even with millions of entries.

- Only hashable objects can be keys. Immutable built-in types are hashable. A tuple is hashable only if everything inside it is.
- Objects that compare equal must have equal hashes. This is why `1` and `1.0` count as the same key.
- Do not depend on specific hash values. String hashes change between program runs for security reasons.

```python
print(hash("abc") == hash("abc"))    # True within one run
{[1, 2]: "x"}                        # TypeError: unhashable type: 'list'
```

## Basic Examples

Counting words:

```python
text = "the cat and the hat and the bat"
counts = {}
for word in text.split():
    counts[word] = counts.get(word, 0) + 1
print(counts)    # {'the': 3, 'cat': 1, 'and': 2, 'hat': 1, 'bat': 1}
```

A lookup table:

```python
country_codes = {"BD": "Bangladesh", "IN": "India", "JP": "Japan"}
code = "JP"
print(country_codes.get(code, "Unknown"))
```

## Backend Industry Example

Totals and grouping over records, applying configuration overrides, and reading optional fields from JSON data.

```python
from decimal import Decimal

orders = [
    {"id": 1, "customer": "amina", "status": "paid", "total": Decimal("120.00")},
    {"id": 2, "customer": "bilal", "status": "pending", "total": Decimal("35.50")},
    {"id": 3, "customer": "amina", "status": "paid", "total": Decimal("260.00")},
]

# Revenue per customer
totals_by_customer: dict[str, Decimal] = {}
for order in orders:
    customer = order["customer"]
    totals_by_customer[customer] = (
        totals_by_customer.get(customer, Decimal("0")) + order["total"]
    )
print(totals_by_customer)    # {'amina': Decimal('380.00'), 'bilal': Decimal('35.50')}

# Group order ids by status
ids_by_status: dict[str, list[int]] = {}
for order in orders:
    ids_by_status.setdefault(order["status"], []).append(order["id"])
print(ids_by_status)         # {'paid': [1, 3], 'pending': [2]}

# Index records by id for fast lookup
orders_by_id = {order["id"]: order for order in orders}
print(orders_by_id[3]["customer"])    # amina

# Default settings with per-environment overrides
DEFAULT_SETTINGS = {"timeout": 5, "retries": 3, "verify_tls": True}


def build_settings(overrides: dict) -> dict:
    """Return settings with the overrides applied, leaving the defaults intact."""
    return DEFAULT_SETTINGS | overrides


print(build_settings({"timeout": 30}))


# Reading optional fields from JSON received from a client
def get_city(user: dict) -> str | None:
    """Return the user's city if the address and city are present."""
    address = user.get("address") or {}
    return address.get("city")


print(get_city({"name": "Amina"}))                        # None
print(get_city({"address": {"city": "Chattogram"}}))      # Chattogram
```

Indexing a list of records into a dictionary by ID changes each lookup from a scan through the whole list into a single step. `user.get("address") or {}` also handles the case where the client sends `"address": null`.

## Common Mistakes

- Using `d[key]` for data that may be missing instead of `d.get(key)`.
- Changing a dictionary's size while iterating over it.
- Using a mutable object such as a list as a key.
- Creating shared values with `dict.fromkeys(keys, [])`, where every key refers to the same list.
- Assuming a key is absent because `get` returned `None`, when the stored value may itself be `None`.
- Relying on dictionaries for ordering rules a reader would not expect.

## Summary

Dictionaries map hashable keys to values with fast lookup. Use `get` for safe reads, `setdefault` for grouping, `|` for merging, and comprehensions for transformation. They keep insertion order. Hashing explains the speed and the rule that keys must be hashable. Most backend data, from JSON bodies to caches and indexes, is shaped like a dictionary.
