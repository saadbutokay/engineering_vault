# 2.7 Algorithmic Helpers

## Overview

Choosing a data structure is also choosing how fast your code will be as data grows. This module introduces Big-O notation, a way to describe that growth, and two standard-library modules, `heapq` and `bisect`, that provide efficient building blocks for priority queues and sorted lookups.

## Big-O Notation

Big-O notation describes how the running time of an operation grows as the input size `n` grows. It ignores constant factors and small details and keeps only the dominant trend.

| Notation | Name | Meaning | Example |
| --- | --- | --- | --- |
| O(1) | constant | time does not depend on `n` | dictionary lookup, list index |
| O(log n) | logarithmic | doubling `n` adds one step | binary search |
| O(n) | linear | time grows in proportion to `n` | scanning a list |
| O(n log n) | linearithmic | slightly worse than linear | sorting |
| O(n^2) | quadratic | doubling `n` makes it four times slower | nested loops over the same data |

Three ideas to keep in mind:

- Worst case, average case, and amortized cost can differ. A list `append` is O(1) amortized: occasionally the list must grow and copy itself, but averaged over many appends the cost is constant.
- Big-O describes growth, not absolute speed. For small inputs an O(n) approach with a small constant can beat an O(1) approach with a large one.
- Measure before optimizing. Big-O tells you where to look and the profiler tells you whether it matters.

Counting steps makes the idea concrete:

```python
def find_linear(items, target):
    for index, item in enumerate(items):    # up to n comparisons: O(n)
        if item == target:
            return index
    return -1

def has_duplicates_slow(items):
    for i in range(len(items)):             # n times
        for j in range(i + 1, len(items)):  # up to n times: O(n^2) in total
            if items[i] == items[j]:
                return True
    return False

def has_duplicates_fast(items):
    return len(set(items)) != len(items)    # one pass: O(n)
```

## Time Complexity of Built-in Operations

Lists:

| Operation | Cost |
| --- | --- |
| `items[i]`, `len(items)` | O(1) |
| `items.append(x)`, `items.pop()` | O(1) amortized |
| `items.pop(0)`, `items.insert(0, x)`, `items.insert(i, x)` | O(n) |
| `x in items`, `items.index(x)`, `items.remove(x)` | O(n) |
| `items.sort()`, `sorted(items)` | O(n log n) |
| `items[a:b]` slice | O(b - a) |
| `items.copy()` | O(n) |

Dictionaries and sets (average case):

| Operation | Cost |
| --- | --- |
| `d[key]`, `d[key] = v`, `del d[key]`, `key in d` | O(1) |
| `s.add(x)`, `s.remove(x)`, `x in s` | O(1) |
| `a \| b` for sets | O(len(a) + len(b)) |
| `a & b` for sets | O(min(len(a), len(b))) |
| iterating over either | O(n) |

Other structures:

| Structure | Operation | Cost |
| --- | --- | --- |
| `deque` | append and pop at either end | O(1) |
| `deque` | index into the middle | O(n) |
| `heapq` | push and pop | O(log n) |
| `heapq` | `heapify` a list | O(n) |
| `bisect` | find a position in a sorted list | O(log n) |
| `bisect.insort` | insert into a sorted list | O(n) |
| `str` | building by repeated `+=` in a loop | O(n^2) overall, prefer `join` |

## heapq

A heap keeps the smallest item at the front and lets you add items and remove the smallest efficiently. `heapq` implements a min-heap on top of an ordinary list. It is the standard tool for priority queues.

```python
import heapq

heap = []
heapq.heappush(heap, 5)
heapq.heappush(heap, 1)
heapq.heappush(heap, 3)

print(heap[0])                # 1, the smallest item is always first (peek)
print(heapq.heappop(heap))    # 1, remove and return the smallest
print(heapq.heappop(heap))    # 3

numbers = [9, 4, 7, 1, 8]
heapq.heapify(numbers)        # rearrange an existing list into a heap in O(n)

print(heapq.nsmallest(2, [9, 4, 7, 1, 8]))    # [1, 4]
print(heapq.nlargest(2, [9, 4, 7, 1, 8]))     # [9, 8]
```

Notes:

- The list is only partly ordered. Only `heap[0]` is guaranteed to be the smallest, so do not sort it by reading in order. Pop repeatedly to get sorted output.
- For a max-heap, push negated values.
- `nlargest` and `nsmallest` accept a `key=` function and are efficient for small `k`.
- Store `(priority, item)` tuples to attach work to a priority. If two priorities are equal, Python compares the next tuple element, which fails if those items cannot be compared. Insert a unique counter as the second element to break ties.

```python
import heapq

tasks = []
heapq.heappush(tasks, (2, "send email"))
heapq.heappush(tasks, (1, "charge card"))
heapq.heappush(tasks, (3, "update cache"))
print(heapq.heappop(tasks))    # (1, 'charge card')
```

## bisect

`bisect` finds positions in an already sorted list using binary search, which takes O(log n) steps.

```python
from bisect import bisect_left, bisect_right, insort

values = [10, 20, 20, 30, 40]

print(bisect_left(values, 20))     # 1, leftmost position where 20 could go
print(bisect_right(values, 20))    # 3, position after the existing 20s
print(bisect_left(values, 25))     # 3

insort(values, 25)                 # insert while keeping the list sorted
print(values)                      # [10, 20, 20, 25, 30, 40]
```

The list must already be sorted, otherwise the result is meaningless. `bisect` also accepts a `key=` argument in Python 3.10 and newer.

A classic use is mapping a number to a bracket:

```python
from bisect import bisect_right

def grade(score):
    breakpoints = [60, 70, 80, 90]
    letters = "FDCBA"
    return letters[bisect_right(breakpoints, score)]

print(grade(55), grade(70), grade(95))    # F C A
```

## Basic Examples

```python
import heapq
import timeit

# Three smallest and three largest
scores = [88, 92, 79, 65, 95, 70, 85]
print(heapq.nsmallest(3, scores))    # [65, 70, 79]
print(heapq.nlargest(3, scores))     # [95, 92, 88]

# Comparing a list and a set for membership
items_list = list(range(50_000))
items_set = set(items_list)
print(timeit.timeit(lambda: 49_999 in items_list, number=500))
print(timeit.timeit(lambda: 49_999 in items_set, number=500))
```

## Backend Industry Example

A job scheduler that always runs the earliest due job, a pricing tier lookup using binary search, and replacing a quadratic duplicate check with a linear one.

```python
import heapq
from bisect import bisect_right
from itertools import count

# 1. Scheduler: a heap of (run_at, tie_breaker, job_name)
tie_breaker = count()      # produces 0, 1, 2, ... so equal times never compare names
job_queue: list[tuple[float, int, str]] = []


def schedule(queue: list, run_at: float, job_name: str) -> None:
    """Add a job to run at a given time."""
    heapq.heappush(queue, (run_at, next(tie_breaker), job_name))


def pop_due_jobs(queue: list, now: float) -> list[str]:
    """Remove and return the names of all jobs due at or before now."""
    due = []
    while queue and queue[0][0] <= now:
        due.append(heapq.heappop(queue)[2])
    return due


schedule(job_queue, 30.0, "send reminders")
schedule(job_queue, 10.0, "expire sessions")
schedule(job_queue, 10.0, "refresh cache")
print(pop_due_jobs(job_queue, now=15.0))    # ['expire sessions', 'refresh cache']
print(pop_due_jobs(job_queue, now=40.0))    # ['send reminders']


# 2. The five slowest requests out of a large stream, without sorting everything
request_times = [("GET /a", 0.12), ("GET /b", 2.40), ("POST /c", 0.80),
                 ("GET /d", 1.75), ("GET /e", 0.05), ("POST /f", 3.10)]
slowest = heapq.nlargest(3, request_times, key=lambda item: item[1])
print(slowest)    # [('POST /f', 3.1), ('GET /b', 2.4), ('GET /d', 1.75)]


# 3. Pricing tier from monthly spend, found with binary search
TIER_THRESHOLDS = [0, 1_000, 5_000, 20_000]
TIER_NAMES = ["free", "basic", "pro", "enterprise"]


def tier_for(monthly_spend: int) -> str:
    """Return the pricing tier for a monthly spend amount."""
    if monthly_spend < 0:
        raise ValueError("monthly_spend must not be negative")
    return TIER_NAMES[bisect_right(TIER_THRESHOLDS, monthly_spend) - 1]


print(tier_for(0), tier_for(999), tier_for(1_000), tier_for(25_000))
# free free basic enterprise


# 4. Finding duplicate order ids in a single pass
def find_duplicates(order_ids: list[str]) -> set[str]:
    """Return the ids that appear more than once, in O(n) time."""
    seen: set[str] = set()
    duplicates: set[str] = set()
    for order_id in order_ids:
        if order_id in seen:
            duplicates.add(order_id)
        seen.add(order_id)
    return duplicates


print(find_duplicates(["A1", "B2", "A1", "C3", "B2", "A1"]))    # {'A1', 'B2'}
```

The `itertools.count` object produces an ever-increasing number, so two jobs scheduled for the same time are ordered by when they were scheduled and Python never has to compare job names. In production the same scheduling pattern appears in task queues and retry timers.

## Common Mistakes

- Using a list for membership checks on large data when a set would do.
- Writing nested loops over the same data and not noticing the O(n^2) cost.
- Using `bisect` on a list that is not sorted.
- Using `heapq` and expecting the whole list to be sorted.
- Pushing items with equal priority that cannot be compared with each other.
- Optimizing before measuring. Complexity helps you find suspects, a profiler confirms them.
- Building a long string with repeated `+=` instead of `join`.

## Summary

Big-O notation describes how cost grows with input size. Know the costs of the built-in operations: dictionary and set lookups are O(1), list scans are O(n), sorting is O(n log n), and operations at the front of a list are O(n). Use `heapq` when you repeatedly need the smallest item, and `bisect` for fast lookups and insertions in sorted lists. Choosing the right structure usually matters more than any micro-optimization.
