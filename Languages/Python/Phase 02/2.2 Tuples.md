# 2.2 Tuples

## Overview

A tuple is an ordered, immutable collection. Once created, its items cannot be added, removed, or replaced. Tuples represent fixed groups of related values such as coordinates, database rows, and function results with several parts.

## Creation

```python
point = (3, 4)
also_point = 3, 4            # parentheses are optional
single = (5,)                # the comma makes it a tuple
not_a_tuple = (5)            # just the number 5
empty = ()
from_list = tuple([1, 2, 3])
```

The comma, not the parentheses, creates a tuple. A single-item tuple needs a trailing comma.

## Immutability

```python
point = (3, 4)
point[0] = 10     # TypeError: 'tuple' object does not support item assignment
```

Immutability is shallow. The tuple's own slots cannot change, but a mutable object stored inside it can.

```python
record = ("config", [1, 2])
record[1].append(3)
print(record)     # ('config', [1, 2, 3])
```

## Indexing, Slicing, and Methods

Indexing, slicing, `len`, `in`, `+`, and `*` work as they do for lists and always produce new tuples. A tuple has only two methods:

```python
t = (1, 2, 2, 3)
print(t.count(2))    # 2
print(t.index(3))    # 3
print(t[1:3])        # (2, 2)
print((1, 2) + (3,)) # (1, 2, 3)
print((1, 2) < (1, 3))  # True: compared item by item
```

## Packing and Unpacking

Packing collects values into a tuple. Unpacking assigns the items to separate names.

```python
point = 3, 4              # packing
x, y = point              # unpacking
print(x, y)               # 3 4

a, b = 1, 2
a, b = b, a               # swap without a temporary variable

x, y, z = (1, 2)          # ValueError: not enough values to unpack
```

Unpacking works with any iterable, in loops, and in function results:

```python
pairs = [("Amina", 90), ("Bilal", 75)]
for name, score in pairs:
    print(name, score)

def min_max(values):
    return min(values), max(values)    # returns one tuple

low, high = min_max([4, 9, 1])
```

Use `_` for a value you do not need: `name, _, age = ("Amina", "x", 30)`.

## Star Unpacking

A starred name collects the leftover items into a list.

```python
first, *rest = [1, 2, 3, 4]
print(first, rest)          # 1 [2, 3, 4]

*init, last = [1, 2, 3, 4]
print(init, last)           # [1, 2, 3] 4

head, *middle, tail = [1, 2, 3, 4, 5]
print(middle)               # [2, 3, 4]
```

Only one starred name is allowed in an unpacking target.

## Tuples as Records

A tuple works well as a fixed-shape record where position carries meaning.

```python
user = ("A-1001", "amina@example.com", 31)
user_id, email, age = user
```

When a record grows beyond three or four fields, positions become hard to remember. At that point use a named structure such as a `namedtuple` or a dataclass so fields can be read by name.

## Tuples versus Lists

| | Tuple | List |
| --- | --- | --- |
| Mutable | no | yes |
| Typical use | fixed group of different things | growing collection of similar things |
| Hashable | yes, if all items are hashable | no |
| Can be a dictionary key | yes | no |
| Communicates | "this will not change" | "this may grow or change" |

Prefer a tuple when the number of items is fixed and each position has its own meaning, such as `(latitude, longitude)`. Prefer a list for a collection of similar items that changes, such as a list of order IDs.

Because tuples are hashable when their contents are, they can be dictionary keys and set members:

```python
distances = {("Dhaka", "Chattogram"): 244, ("Dhaka", "Sylhet"): 240}
print(distances[("Dhaka", "Sylhet")])    # 240

hash(([1, 2], 3))    # TypeError: unhashable type: 'list'
```

## Basic Examples

```python
rgb = (255, 128, 0)
red, green, blue = rgb

def divide(a, b):
    return a // b, a % b

quotient, remainder = divide(17, 5)
print(quotient, remainder)    # 3 2

scores = (90, 85, 70, 60)
best, *others = scores
print(best, others)           # 90 [85, 70, 60]
```

## Backend Industry Example

Tuples as composite dictionary keys, as multi-value returns, and for taking apart database rows.

```python
# Counting requests per client and endpoint with a composite key
request_counts: dict[tuple[str, str], int] = {}


def record_request(client_id: str, endpoint: str) -> int:
    """Count one request and return the new total for this client and endpoint."""
    key = (client_id, endpoint)
    request_counts[key] = request_counts.get(key, 0) + 1
    return request_counts[key]


record_request("client-7", "/orders")
record_request("client-7", "/orders")
record_request("client-7", "/users")
print(request_counts)
# {('client-7', '/orders'): 2, ('client-7', '/users'): 1}


# Returning the data and the cursor for the next page together
def get_page(
    all_ids: list[int], cursor: int, size: int
) -> tuple[list[int], int | None]:
    """Return one page of ids and the cursor for the next page, or None at the end."""
    page = all_ids[cursor:cursor + size]
    next_cursor = cursor + size if cursor + size < len(all_ids) else None
    return page, next_cursor


page, next_cursor = get_page(list(range(1, 8)), cursor=0, size=3)
print(page, next_cursor)    # [1, 2, 3] 3


# Taking apart a row where only the first fields have a fixed meaning
def summarize_row(row: tuple) -> str:
    order_id, email, *line_items = row
    return f"{order_id} for {email} with {len(line_items)} items"


print(summarize_row(("A-1001", "amina@example.com", "pen", "notebook")))
# A-1001 for amina@example.com with 2 items
```

The composite key avoids building strings like `"client-7:/orders"` and splitting them later. The type hint `dict[tuple[str, str], int]` documents what the key looks like.

## Common Mistakes

- Forgetting the trailing comma in a single-item tuple.
- Assuming a tuple is deeply immutable when it holds lists or dictionaries.
- Unpacking into the wrong number of names.
- Using a tuple for data that needs to grow.
- Using a list as a dictionary key and getting `TypeError: unhashable type`.
- Using position-based tuples for records with many fields.

## Summary

Tuples are immutable ordered collections created by commas. Packing and unpacking, including star unpacking, make multi-value assignments and returns clean. Use tuples for fixed-shape records and as dictionary keys, and use lists for collections that change. Immutability is shallow, so a mutable object stored inside a tuple can still be changed.
