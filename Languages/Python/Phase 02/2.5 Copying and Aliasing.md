# 2.5 Copying and Aliasing

## Overview

Assigning a mutable object to another name does not copy it. Both names refer to the same object, so a change through one name appears through the other. This is called aliasing. Knowing when two names share one object, and how to make real copies, prevents some of the most confusing bugs in Python.

## References and Aliasing

```python
a = [1, 2, 3]
b = a              # b is another name for the same list
b.append(4)
print(a)           # [1, 2, 3, 4]
print(a is b)      # True
```

The same thing happens when you pass an object to a function. The function receives a reference to the caller's object.

```python
def add_item(items):
    items.append("new")       # changes the caller's list

shopping = ["milk"]
add_item(shopping)
print(shopping)               # ['milk', 'new']
```

Rebinding the parameter name does not affect the caller, only changing the object does:

```python
def replace(items):
    items = ["other"]         # rebinds the local name, caller unaffected

replace(shopping)
print(shopping)               # ['milk', 'new']
```

Immutable objects cannot be changed through an alias, so aliasing only causes surprises with mutable ones such as lists, dictionaries, and sets.

## Shallow Copy

A shallow copy creates a new outer container but reuses the same inner objects.

```python
import copy

original = [1, 2, 3]
copy1 = original.copy()
copy2 = list(original)
copy3 = original[:]
copy4 = copy.copy(original)

user = {"name": "Amina"}
user_copy = user.copy()          # also dict(user) or {**user}
```

For a list of numbers or strings, a shallow copy is enough. Problems appear with nested mutable objects.

```python
matrix = [[1, 2], [3, 4]]
shallow = matrix.copy()
shallow[0].append(99)
print(matrix)      # [[1, 2, 99], [3, 4]]  the inner list is shared
print(shallow[0] is matrix[0])   # True
```

## Deep Copy

`copy.deepcopy` copies the container and everything inside it, recursively.

```python
import copy

matrix = [[1, 2], [3, 4]]
deep = copy.deepcopy(matrix)
deep[0].append(99)
print(matrix)      # [[1, 2], [3, 4]]  unchanged
print(deep)        # [[1, 2, 99], [3, 4]]
```

Deep copies cost time and memory proportional to the size of the data. Use them when you truly need independence, not by habit.

## Common Bugs Aliasing Causes

Repeated rows in a grid:

```python
grid = [[0] * 3] * 3          # three references to one row
grid[0][0] = 1
print(grid)                   # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]
```

Shared values from `dict.fromkeys`:

```python
inbox = dict.fromkeys(["amina", "bilal"], [])
inbox["amina"].append("hello")
print(inbox)                  # {'amina': ['hello'], 'bilal': ['hello']}

inbox = {name: [] for name in ["amina", "bilal"]}   # correct: one list per key
```

Mutating a default that is shared by every caller:

```python
def add_tag(tag, tags=[]):    # the default list is created once and reused
    tags.append(tag)
    return tags

print(add_tag("a"))           # ['a']
print(add_tag("b"))           # ['a', 'b']  surprising
```

Fix it by using `None` as the default and creating a new list inside the function:

```python
def add_tag(tag, tags=None):
    if tags is None:
        tags = []
    tags.append(tag)
    return tags
```

## Basic Examples

```python
original = {"name": "Amina", "scores": [90, 85]}

alias = original
shallow = original.copy()
deep = copy.deepcopy(original)

original["name"] = "Bilal"
original["scores"].append(70)

print(alias["name"], alias["scores"])       # Bilal [90, 85, 70]
print(shallow["name"], shallow["scores"])   # Amina [90, 85, 70] list is shared
print(deep["name"], deep["scores"])         # Amina [90, 85] fully independent
```

## Backend Industry Example

Module-level default configuration is shared by every request. A shallow copy leaks changes between tenants, while a deep copy keeps each request isolated.

```python
import copy

DEFAULT_CONFIG = {
    "retry": {"attempts": 3, "delay": 1.0},
    "hosts": ["api-1.example.com"],
}


def config_for_tenant_buggy(overrides: dict) -> dict:
    config = DEFAULT_CONFIG.copy()           # shallow: inner objects are shared
    config["retry"]["attempts"] = overrides.get("attempts", 3)
    config["hosts"].extend(overrides.get("extra_hosts", []))
    return config


def config_for_tenant(overrides: dict) -> dict:
    """Return an independent configuration for one tenant."""
    config = copy.deepcopy(DEFAULT_CONFIG)
    config["retry"]["attempts"] = overrides.get("attempts", 3)
    config["hosts"].extend(overrides.get("extra_hosts", []))
    return config


config_for_tenant_buggy({"attempts": 9, "extra_hosts": ["api-2.example.com"]})
print(DEFAULT_CONFIG)
# the defaults are now corrupted for every later caller

DEFAULT_CONFIG = {
    "retry": {"attempts": 3, "delay": 1.0},
    "hosts": ["api-1.example.com"],
}
config_for_tenant({"attempts": 9, "extra_hosts": ["api-2.example.com"]})
print(DEFAULT_CONFIG)
# the defaults are unchanged


def with_audit_fields(record: dict) -> dict:
    """Return a new record with audit fields and leave the input untouched."""
    return {**record, "audited": True}
```

A function that silently changes its argument surprises its callers. Either document the mutation clearly or, as in `with_audit_fields`, return a new object. Another approach is to use immutable types such as tuples and frozen data classes, which cannot be changed through an alias at all.

## Common Mistakes

- Writing `b = a` and expecting a copy.
- Using a shallow copy on nested data and mutating the inner objects.
- Overusing `deepcopy`, which is slow for large structures.
- Creating grids with `[[0] * n] * m`.
- Using mutable default arguments.
- Modifying an argument inside a function without telling the caller.

## Summary

Assignment and argument passing share objects instead of copying them. A shallow copy duplicates only the outer container, while `copy.deepcopy` duplicates everything inside as well. Use `is` to check whether two names refer to the same object, create new containers when you need independence, and treat module-level defaults as read-only.
