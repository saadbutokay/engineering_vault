# 2.6 The collections Module

## Overview

The `collections` module in the standard library provides specialized containers that solve common problems more clearly than the basic types: counting, grouping, queues, named records, and layered lookups.

## defaultdict

A `defaultdict` creates a default value automatically when you access a missing key. You give it a factory function that produces the default.

```python
from collections import defaultdict

groups = defaultdict(list)
for word in ["apple", "avocado", "banana", "blueberry"]:
    groups[word[0]].append(word)
print(dict(groups))   # {'a': ['apple', 'avocado'], 'b': ['banana', 'blueberry']}

counts = defaultdict(int)       # int() returns 0
for letter in "banana":
    counts[letter] += 1
print(dict(counts))   # {'b': 1, 'a': 3, 'n': 2}
```

Common factories: `list`, `int`, `set`, and `lambda: some_value`. One thing to watch: merely reading a missing key creates it.

```python
d = defaultdict(list)
d["missing"]
print(d)    # defaultdict(<class 'list'>, {'missing': []})
```

Use `"key" in d` or `d.get("key")` when you need to check without creating.

## Counter

A `Counter` is a dictionary specialized for counting hashable items. Missing items count as zero.

```python
from collections import Counter

counts = Counter("banana")
print(counts)                    # Counter({'a': 3, 'n': 2, 'b': 1})
print(counts["a"], counts["z"])  # 3 0
print(counts.most_common(2))     # [('a', 3), ('n', 2)]

counts.update("band")            # add more observations
counts.subtract("ban")           # remove observations
print(counts.total())            # sum of all counts

words = Counter(["red", "blue", "red", "green", "red"])
print(words.most_common(1))      # [('red', 3)]
print(Counter(a=2, b=1) + Counter(a=1, c=5))   # Counter({'c': 5, 'a': 3, 'b': 1})
```

## deque

A `deque` (double-ended queue, pronounced "deck") adds and removes items at either end in constant time. A list is slow at the front, a deque is fast at both ends.

```python
from collections import deque

queue = deque([1, 2, 3])
queue.append(4)            # right end: deque([1, 2, 3, 4])
queue.appendleft(0)        # left end: deque([0, 1, 2, 3, 4])
print(queue.pop())         # 4
print(queue.popleft())     # 0
queue.rotate(1)            # rotate right by one step

recent = deque(maxlen=3)   # keeps only the 3 most recent items
for n in range(6):
    recent.append(n)
print(recent)              # deque([3, 4, 5], maxlen=3)
```

Use a deque for first-in first-out queues and sliding windows. Indexing into the middle of a deque is slow, so it is not a replacement for a list in general.

## namedtuple

A `namedtuple` is a tuple whose positions also have names. It is immutable and as lightweight as a tuple.

```python
from collections import namedtuple

Point = namedtuple("Point", ["x", "y"])
p = Point(3, 4)
print(p.x, p.y)        # 3 4
print(p[0])            # 3, still works like a tuple
x, y = p               # still unpacks

p2 = p._replace(x=10)  # new tuple with one field changed
print(p2)              # Point(x=10, y=4)
print(p._asdict())     # {'x': 3, 'y': 4}
```

A namedtuple is useful for small, read-only records where field names improve readability.

## ChainMap

A `ChainMap` groups several dictionaries into one view and searches them in order. The first dictionary that contains the key wins. Writes go to the first dictionary only.

```python
from collections import ChainMap

defaults = {"color": "red", "size": "M"}
user_choices = {"color": "blue"}

settings = ChainMap(user_choices, defaults)
print(settings["color"])    # blue, found in user_choices
print(settings["size"])     # M, found in defaults

settings["size"] = "L"      # stored in user_choices, defaults unchanged
print(defaults["size"])     # M
print(settings.maps)        # the list of underlying dictionaries
```

It avoids copying and merging dictionaries when you only need layered lookups.

## Basic Examples

```python
from collections import Counter, defaultdict, deque

# Most common word
text = "to be or not to be that is the question to"
print(Counter(text.split()).most_common(1))    # [('to', 3)]

# Group names by length
by_length = defaultdict(list)
for name in ["Amina", "Bilal", "Chen", "Dara", "Elena"]:
    by_length[len(name)].append(name)
print(dict(by_length))

# Last three commands typed
history = deque(maxlen=3)
for command in ["ls", "cd", "git status", "pytest"]:
    history.append(command)
print(list(history))    # ['cd', 'git status', 'pytest']
```

## Backend Industry Example

Analyzing access logs with `Counter`, limiting request rates with a `deque` sliding window, and resolving settings from several layers with `ChainMap`.

```python
from collections import ChainMap, Counter, deque

# 1. Access log analysis
log_lines = [
    "GET /orders 200",
    "GET /orders 200",
    "POST /orders 500",
    "GET /users 404",
    "GET /orders 200",
]

status_counts: Counter[str] = Counter()
endpoint_counts: Counter[str] = Counter()
for line in log_lines:
    method, path, status = line.split()
    status_counts[status] += 1
    endpoint_counts[path] += 1

print(status_counts.most_common())      # [('200', 3), ('500', 1), ('404', 1)]
print(endpoint_counts.most_common(1))   # [('/orders', 4)]

error_rate = sum(
    count for status, count in status_counts.items() if status.startswith("5")
) / status_counts.total()
print(f"{error_rate:.0%}")              # 20%


# 2. Sliding-window rate limiter: at most N requests in the last W seconds
def allow_request(
    timestamps: deque[float], now: float, max_requests: int, window: float
) -> bool:
    """Record the request and return True if it is within the rate limit."""
    cutoff = now - window
    while timestamps and timestamps[0] <= cutoff:
        timestamps.popleft()                 # forget requests outside the window
    if len(timestamps) >= max_requests:
        return False
    timestamps.append(now)
    return True


recent_requests: deque[float] = deque()
results = [allow_request(recent_requests, t, max_requests=3, window=10.0)
           for t in [0, 1, 2, 3, 11, 12]]
print(results)    # [True, True, True, False, True, True]


# 3. Layered configuration: command line beats environment beats defaults
defaults = {"port": 8000, "debug": False, "log_level": "INFO"}
env_settings = {"port": 9000}
cli_args = {"debug": True}

settings = ChainMap(cli_args, env_settings, defaults)
print(settings["port"], settings["debug"], settings["log_level"])
# 9000 True INFO
```

The deque removes expired timestamps from the left in constant time, which would be slow with a list. `ChainMap` keeps each configuration source separate, so it is always clear where a value came from.

## Common Mistakes

- Reading a missing key from a `defaultdict` and unintentionally creating it.
- Using a list as a queue with `pop(0)` when a deque is the right tool.
- Forgetting that `Counter` treats missing items as zero, which hides typos in keys.
- Expecting a `namedtuple` to be mutable.
- Passing a function call instead of a function to `defaultdict`: `defaultdict(list())` is wrong, `defaultdict(list)` is right.
- Expecting writes to a `ChainMap` to update the lower layers.

## Summary

Use `defaultdict` for grouping and accumulating, `Counter` for frequency counts and top-N questions, `deque` for queues and sliding windows, `namedtuple` for small named records, and `ChainMap` for layered lookups. Each replaces boilerplate that you would otherwise write by hand with a plain dictionary or list.
