# 0.4 Code Editor Setup

## Overview

A good editor setup removes friction: it finds the correct interpreter, highlights mistakes as you type, runs your code with one key, and lets you pause a program and inspect it. This module sets up Visual Studio Code (VS Code) for Python work.

## Installing VS Code and the Python Extension

1. Download VS Code from code.visualstudio.com and install it.
2. Open the Extensions view (Ctrl+Shift+X on Windows and Linux, Cmd+Shift+X on macOS).
3. Install the extension named Python, published by Microsoft. It brings language support (Pylance) and debugging with it.
4. Open your project folder with File, then Open Folder. Always open the project root, not a single file.

## Selecting an Interpreter

VS Code must know which Python to use for running, linting, and autocomplete. This should be the interpreter inside your project's virtual environment.

1. Open the Command Palette: Ctrl+Shift+P (Windows and Linux) or Cmd+Shift+P (macOS).
2. Type `Python: Select Interpreter` and press Enter.
3. Choose the entry that points to `.venv` inside your project.

The selected interpreter is shown in the bottom-right status bar. If imports are underlined as unresolved even though the package is installed, the wrong interpreter is almost always the cause.

## Running Code

- Run button: the triangle at the top right of the editor runs the current file.
- Right-click inside the file and choose Run Python File in Terminal.
- Ctrl+F5 runs without the debugger. F5 runs with the debugger.

## Debugging

A debugger lets you pause a running program, look at the values of variables, and execute one line at a time. It replaces guessing with `print` statements.

| Action | Shortcut |
| --- | --- |
| Toggle a breakpoint on the current line | F9 |
| Start debugging or continue | F5 |
| Step over (run the line, do not enter functions) | F10 |
| Step into (enter the function being called) | F11 |
| Step out (finish the current function) | Shift+F11 |
| Stop | Shift+F5 |

Click in the gutter to the left of a line number to place a breakpoint, shown as a red dot. When execution reaches that line the program pauses. The side panel then shows Variables (current values), Watch (expressions you choose), and Call Stack (how the program got here).

## The Integrated Terminal

Open it with Ctrl+` (backtick). When a virtual environment interpreter is selected, VS Code activates the environment automatically in new terminals, and the prompt shows the environment name.

## Basic Examples

Practise debugging with a small function. Place a breakpoint on the line `total += n` and step through with F10, watching `total` change.

```python
def average(numbers):
    total = 0
    for n in numbers:
        total += n
    return total / len(numbers)


scores = [80, 90, 100]
result = average(scores)
print(result)
```

Then call `average([])` and use the debugger to see exactly where the program stops and what `numbers` contains when the `ZeroDivisionError` is raised.

## Backend Industry Example

Teams keep editor behaviour consistent by committing workspace configuration to the repository in a `.vscode` folder.

`.vscode/settings.json`:

```json
{
  "python.defaultInterpreterPath": "${workspaceFolder}/.venv/bin/python",
  "python.terminal.activateEnvironment": true,
  "python.testing.pytestEnabled": true,
  "python.testing.pytestArgs": ["tests"],
  "editor.formatOnSave": true,
  "[python]": {
    "editor.defaultFormatter": "charliermarsh.ruff",
    "editor.codeActionsOnSave": {
      "source.fixAll.ruff": "explicit",
      "source.organizeImports.ruff": "explicit"
    }
  }
}
```

On Windows the interpreter path is `${workspaceFolder}/.venv/Scripts/python.exe`.

`.vscode/launch.json` defines how to start the service and its tests under the debugger:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Orders service: healthcheck",
      "type": "debugpy",
      "request": "launch",
      "module": "orders_service",
      "args": ["healthcheck"],
      "cwd": "${workspaceFolder}",
      "envFile": "${workspaceFolder}/.env",
      "justMyCode": true
    },
    {
      "name": "Pytest: current file",
      "type": "debugpy",
      "request": "launch",
      "module": "pytest",
      "args": ["${file}", "-x"],
      "justMyCode": false
    }
  ]
}
```

Notes on this configuration:

- `module` launches the service the same way production does, with `python -m`.
- `envFile` loads environment variables from `.env` so the debugger sees the same configuration as a normal run.
- `justMyCode` set to `true` skips stepping into library code. Set it to `false` when you need to debug inside a dependency.
- This setup assumes the project was installed in editable mode with `pip install -e .`, which makes the `orders_service` package importable.

## Common Mistakes

- Opening a single file or the wrong folder instead of the project root, so VS Code cannot find the virtual environment or configuration.
- Selecting the global interpreter instead of the project's `.venv`.
- Debugging with the run button instead of F5 and wondering why breakpoints are ignored.
- Having two formatters enabled that fight each other on save.
- Committing personal editor preferences instead of shared project settings.

## Summary

Install VS Code and the Microsoft Python extension, open the project root, and select the interpreter in `.venv`. Learn the breakpoint and stepping shortcuts, because the debugger is the fastest way to understand a failing program. Commit shared settings and launch configurations so every contributor runs and debugs the project the same way.
