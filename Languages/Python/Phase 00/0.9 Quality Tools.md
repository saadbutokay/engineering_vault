# 0.9 Quality Tools

## Overview

Quality tools check your code automatically so reviews can focus on design instead of formatting and avoidable mistakes. This module covers three of them.

| Tool | Job |
| --- | --- |
| `ruff` | A linter (finds likely bugs and style problems) and a formatter (rewrites code into one consistent style) |
| `mypy` | A static type checker that finds type mistakes without running the code |
| `pre-commit` | Runs checks automatically before every Git commit |

Configuration for `ruff` and `mypy` lives in `pyproject.toml`. `pre-commit` is the exception: it has its own file named `.pre-commit-config.yaml`, which calls the other two tools.

## ruff

Install into the project environment:

```bash
python -m pip install ruff
```

Commands:

```bash
ruff check .                # report lint problems
ruff check . --fix          # fix the problems that can be fixed automatically
ruff format .               # reformat code
ruff format --check .       # fail if formatting is needed, without changing files
```

Ruff replaces several older tools: flake8 (linting), isort (import sorting), and Black (formatting).

## mypy

Install and run:

```bash
python -m pip install mypy
mypy src
```

mypy reads type hints and reports inconsistencies. It does not run your code. The examples here only need the basic syntax `name: type` for a variable or parameter and `-> type` for a return value.

## pre-commit

`pre-commit` installs a Git hook. When you run `git commit`, the configured checks run on the changed files and block the commit if they fail.

```bash
python -m pip install pre-commit
pre-commit install               # activate the hook in this repository
pre-commit run --all-files       # run all checks on the whole project now
pre-commit autoupdate            # update hook versions
```

## Configuration in pyproject.toml

```toml
[tool.ruff]
line-length = 88
target-version = "py312"
src = ["src", "tests"]

[tool.ruff.lint]
select = [
    "E",    # pycodestyle errors
    "F",    # pyflakes: unused imports and variables, undefined names
    "I",    # import sorting
    "B",    # likely bugs (flake8-bugbear)
    "UP",   # modernise syntax for newer Python versions
    "N",    # naming conventions
    "SIM",  # simplifiable code
]

[tool.ruff.format]
quote-style = "double"

[tool.mypy]
python_version = "3.12"
strict = true
files = ["src"]
```

`strict = true` turns on mypy's strictest checks. It is easiest to adopt from the first day of a project and painful to add later.

`.pre-commit-config.yaml`:

```yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.14.0
    hooks:
      - id: ruff-check
        args: [--fix]
      - id: ruff-format

  - repo: https://github.com/pre-commit/mirrors-mypy
    rev: v1.18.2
    hooks:
      - id: mypy
        files: ^src/
```

The `rev` values are examples. Run `pre-commit autoupdate` to move them to the current releases. Because pre-commit runs mypy in its own isolated environment, add `additional_dependencies` for any libraries whose types mypy needs to see.

## Basic Examples

A file with problems:

```python
import os
import sys


def add(a: int, b: int) -> int:
    return a+b


print(add("1", 2))
```

Running `ruff check .` reports that `os` and `sys` are imported but unused (rule F401). Running `ruff format .` fixes the spacing in `a+b`. Running `mypy` on the file reports that the first argument to `add` has type `str` where `int` is expected, before the program is ever run.

Fixed version:

```python
def add(a: int, b: int) -> int:
    return a + b


print(add(1, 2))
```

## Backend Industry Example

A fully typed function that passes strict checking, and a single script that runs every check the same way locally and in continuous integration.

```python
# src/orders_service/inventory.py
from dataclasses import dataclass


@dataclass(frozen=True)
class StockItem:
    sku: str
    quantity: int


class OutOfStockError(Exception):
    """Raised when an order asks for more units than are available."""


def reserve_stock(item: StockItem, requested: int) -> StockItem:
    """Return a new StockItem with the requested quantity removed."""
    if requested <= 0:
        raise ValueError("requested quantity must be positive")
    if requested > item.quantity:
        raise OutOfStockError(
            f"{item.sku}: requested {requested}, have {item.quantity}"
        )
    return StockItem(sku=item.sku, quantity=item.quantity - requested)
```

`scripts/check.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

ruff check .
ruff format --check .
mypy
pytest
```

Developers run `pre-commit` for fast feedback on each commit. The continuous integration server runs `scripts/check.sh` on every pull request, so code that violates the standards cannot be merged. `set -euo pipefail` makes the script stop at the first failing command.

## Common Mistakes

- Installing the tools but never running them. Automate with pre-commit and continuous integration.
- Enabling many rules at once on an old codebase and drowning in warnings. Start with a small rule set and extend it.
- Silencing errors with `# type: ignore` or `# noqa` without a comment explaining why.
- Using different tool versions locally and in CI. Pin versions in the lock file and in `.pre-commit-config.yaml`.
- Expecting `pre-commit` to be configured in `pyproject.toml`. It reads `.pre-commit-config.yaml`.

## Summary

Use `ruff` to lint and format, `mypy` to catch type errors early, and `pre-commit` to run both before every commit. Configure ruff and mypy in `pyproject.toml`, keep the pre-commit hook list in its own YAML file, and run the same checks in continuous integration so quality is enforced by machines instead of memory.
