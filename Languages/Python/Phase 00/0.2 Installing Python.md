# 0.2 Installing Python

## Overview

Before writing any Python you need a working interpreter on your machine and a way to manage more than one version of it. This module covers installation on Windows, macOS, and Linux, how to verify it, and how to install `uv`, a fast tool for managing Python versions and packages.

Use a currently supported Python 3 release. The examples in these notes assume Python 3.12 or newer.

## Windows

1. Download the installer from python.org.
2. On the first installer screen, enable the option to add Python to PATH, then choose the install option.
3. Open a new PowerShell window and verify.

```powershell
python --version
py --version
```

The `py` launcher is installed with Python on Windows. It finds installed Python versions without depending on PATH.

```powershell
py -0          # list installed Python versions
py -3.12       # start Python 3.12 specifically
py -3.12 script.py
```

PATH is the list of folders the shell searches when you type a command name. If `python` is not found, the folder containing `python.exe` is not on PATH.

Windows may open the Microsoft Store when you type `python` without an installation. This is an app execution alias, a placeholder for the Store version. Install from python.org, or disable the alias in Windows settings under App execution aliases.

## macOS

Two common options.

- python.org installer: download the macOS installer and run it.
- Homebrew: a package manager for macOS.

```bash
brew install python
```

On macOS the command is `python3`, not `python`.

```bash
python3 --version
```

## Linux

Use the system package manager. Package names for the interpreter, the virtual environment module, and pip are often separate on Debian-based systems.

```bash
# Debian and Ubuntu
sudo apt update
sudo apt install python3 python3-venv python3-pip

# Fedora, RHEL, and derivatives
sudo dnf install python3 python3-pip
```

```bash
python3 --version
```

Linux distributions use Python for their own tools. Never remove or replace the system Python, and avoid installing packages into it. Isolation is handled with virtual environments instead.

## Verifying the Installation

```bash
python3 --version          # macOS and Linux
python --version           # Windows
which python3              # macOS and Linux: where the command comes from
Get-Command python         # PowerShell: where the command comes from
```

The path printed by these commands tells you which interpreter will actually run. When behaviour is confusing, the cause is often that a different Python than the one you expected is being found first.

## Installing uv

`uv` is a tool that installs Python versions, creates virtual environments, and installs packages. It is much faster than pip for most tasks.

```bash
# macOS and Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# macOS with Homebrew
brew install uv
```

```powershell
# Windows PowerShell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Verify:

```bash
uv --version
```

## Managing Multiple Python Versions

Different projects often need different Python versions. Do not try to make one global installation satisfy all of them.

```bash
uv python list              # show available and installed versions
uv python install 3.12      # download and install Python 3.12
uv python install 3.13
uv venv --python 3.12       # create a virtual environment using 3.12
```

On Windows, the `py` launcher also selects versions (`py -3.12`). Another widely used tool for this job is `pyenv` on macOS and Linux.

## Basic Examples

A script that reports which interpreter is running it. Run it with the `python` command you just installed.

```python
import sys

print(sys.version)
print(sys.executable)
```

`sys.version` shows the Python version. `sys.executable` shows the exact interpreter file that is running the script.

## Backend Industry Example

A service should declare which Python versions it supports in three places, and fail early with a clear message when run on an unsupported version.

Declare the requirement in `pyproject.toml`:

```toml
[project]
name = "orders-service"
version = "0.1.0"
requires-python = ">=3.12"
```

Pin the runtime in the container image:

```dockerfile
FROM python:3.12-slim
```

Fail fast at startup:

```python
import sys

MINIMUM_PYTHON = (3, 12)


def ensure_supported_python() -> None:
    """Stop the process early when the interpreter is too old."""
    if sys.version_info < MINIMUM_PYTHON:
        required = ".".join(str(part) for part in MINIMUM_PYTHON)
        found = ".".join(str(part) for part in sys.version_info[:3])
        raise RuntimeError(f"Python {required} or newer is required, found {found}")


if __name__ == "__main__":
    ensure_supported_python()
    print("Interpreter check passed")
```

Failing at startup with a clear message is far cheaper than a confusing syntax error or missing feature appearing in the middle of a request in production.

## Common Mistakes

- Forgetting to enable PATH during the Windows install, then not finding `python`.
- Typing `python` on macOS or Linux where only `python3` exists.
- Installing packages into the system Python instead of a virtual environment.
- Having several Python versions installed and not knowing which one a command uses. Check with `which` or `Get-Command`.
- Running an old interpreter in production while developing on a newer one.

## Summary

Install Python from python.org or a package manager, verify it with `--version`, and confirm which executable runs. Install `uv` for fast version and environment management. Keep multiple Python versions side by side instead of upgrading one global installation, and declare the required version in `pyproject.toml`, your container image, and an early startup check.
