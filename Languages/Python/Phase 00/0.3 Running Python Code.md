# 0.3 Running Python Code

## Overview

There are several ways to run Python: interactively in the REPL, by running a file, by running a module with `python -m`, and by passing arguments to a script. Each has a clear purpose. This module explains them and the difference between the `python` and `python3` commands.

## The REPL

REPL stands for read, evaluate, print, loop. You type one expression, Python evaluates it, prints the result, and waits for the next one. It is ideal for quick experiments.

```text
$ python3
>>> 2 + 3
5
>>> name = "Amina"
>>> name.upper()
'AMINA'
>>> help(str.split)
```

Useful facts:

- `>>>` is the primary prompt and `...` is the continuation prompt for multi-line statements.
- In the interactive session, `_` holds the result of the last expression.
- `help(obj)` shows documentation for an object.
- To exit: type `exit()`, or press Ctrl+D on macOS and Linux, or Ctrl+Z then Enter on Windows.

## Running a File

Save code in a file ending in `.py` and give the filename to the interpreter.

```bash
python3 hello.py        # macOS and Linux
python hello.py         # Windows
```

Python runs the file from top to bottom and then exits. The current working directory is where you launched the command, not where the file lives.

Other useful forms:

```bash
python -c "print('inline code')"     # run a short piece of code from the command line
python -i hello.py                   # run the file, then stay in the REPL with its variables
```

## Running a Module with python -m

The `-m` flag tells Python to find a module by name and run it as a script. It uses the interpreter you typed, and it adds the current directory to the import path.

```bash
python -m venv .venv                 # create a virtual environment
python -m pip install requests       # install a package with this interpreter's pip
python -m http.server 8000           # serve the current folder at http://localhost:8000
python -m json.tool data.json        # pretty-print a JSON file
python -m pytest                     # run tests
```

`python -m pip` is preferred over plain `pip` because it guarantees that pip belongs to the same interpreter that will run your code.

When you run `python -m package_name`, Python executes `package_name/__main__.py`. This is how many tools and services expose an entry point.

## Command-Line Arguments

Arguments after the script name are available in `sys.argv`, a list of strings. Index 0 is the script name.

```bash
python greet.py Amina 3
```

```python
import sys

print("Script name:", sys.argv[0])
print("Arguments:", sys.argv[1:])
```

Output:

```text
Script name: greet.py
Arguments: ['Amina', '3']
```

Every argument arrives as a string. Convert with `int()` or `float()` when you need numbers. Libraries such as `argparse` handle parsing properly.

## python versus python3

| Platform | What to type |
| --- | --- |
| Windows | `python` or the `py` launcher |
| macOS | `python3` (a `python` command may not exist) |
| Linux | `python3` (on very old systems `python` meant Python 2) |
| Inside an active virtual environment | `python` always points to the environment's interpreter |

Python 2 is obsolete. Always target Python 3.

## Basic Examples

A script that greets the person named on the command line:

```python
import sys

if len(sys.argv) < 2:
    print("Usage: python greet.py NAME")
else:
    name = sys.argv[1]
    print(f"Hello, {name}!")
```

The special variable `__name__` equals `"__main__"` only when the file is run directly. This lets a file work both as a runnable script and as an importable module.

```python
def add(a, b):
    return a + b


if __name__ == "__main__":
    print(add(2, 3))
```

## Backend Industry Example

Services and tools expose a single entry point that returns an exit code. Exit code 0 means success and any non-zero value means failure. Process managers, CI systems, and container orchestrators read that code to decide whether to restart, alert, or fail a deployment.

```python
# src/orders_service/__main__.py
import sys


def main(argv: list[str] | None = None) -> int:
    """Run the command given in argv and return a process exit code."""
    args = argv if argv is not None else sys.argv[1:]

    if not args:
        print("usage: python -m orders_service <command>", file=sys.stderr)
        return 2

    command = args[0]
    if command == "healthcheck":
        print("ok")
        return 0

    print(f"unknown command: {command}", file=sys.stderr)
    return 1


if __name__ == "__main__":
    raise SystemExit(main())
```

Run it:

```bash
python -m orders_service healthcheck
echo $?                      # macOS and Linux: prints 0
```

```powershell
python -m orders_service healthcheck
$LASTEXITCODE                # PowerShell: prints 0
```

Points worth copying: `main` accepts `argv` so it can be tested without launching a process, error messages go to standard error with `file=sys.stderr`, and the exit code is returned rather than hidden inside the function.

## Common Mistakes

- Running `pip` instead of `python -m pip` and installing into a different interpreter than expected.
- Forgetting that `sys.argv` values are strings.
- Putting executable code at module level without a `__main__` guard, so merely importing the file runs it.
- Running a script from the wrong directory and breaking relative paths.
- Calling `exit()` from library code instead of returning or raising, which makes the code hard to test.

## Summary

Use the REPL for experiments, `python file.py` to run scripts, and `python -m module` to run tools and package entry points. Read arguments from `sys.argv`, remembering they are strings. Use `python3` on macOS and Linux and `python` or `py` on Windows. Production entry points return meaningful exit codes.
