# 0.1 How Programs Run and the Terminal

## Overview

A program is a list of instructions that a computer follows. Every script, backend service, and command-line tool you will write is a program. This module explains how those instructions get executed and how you talk to your computer through the terminal, which is the main working environment for everything that follows.

## What a Program Is

A program is a file, or a set of files, containing instructions written in a programming language. A processor only understands machine code, so human-readable source code must be translated before it can run. There are two classic strategies for that translation.

| Approach | How it works | Typical languages |
| --- | --- | --- |
| Compiler | Translates the whole program into machine code before it runs and produces an executable file | C, C++, Go, Rust |
| Interpreter | Reads the program and executes it while running, translating as it goes | Python, Ruby |

Python sits in between. The reference implementation, CPython, first compiles your source code into bytecode (a compact intermediate form, often cached in `__pycache__` as `.pyc` files). A virtual machine then interprets that bytecode. In daily practice Python feels interpreted: there is no separate build step, and you run the source file directly.

The trade-off is feedback speed versus raw speed. Interpreted workflows give fast feedback while developing. Compiled languages usually run faster and catch more mistakes before the program starts.

## Terminal and Shell

These two words are often used as if they mean the same thing, but they are different.

- Terminal (terminal emulator): the window that displays text and accepts keyboard input. Examples: Windows Terminal, macOS Terminal, GNOME Terminal.
- Shell: the program running inside the terminal that reads each command you type, executes it, and prints the result.

| Operating system | Default shell |
| --- | --- |
| Windows | PowerShell |
| macOS | zsh |
| Linux | bash (on most distributions) |

A command has a consistent shape: the command name, then options (also called flags), then arguments.

```text
ls -l /tmp
```

Here `ls` is the command, `-l` is an option, and `/tmp` is an argument.

## Essential Commands

| Task | PowerShell (Windows) | zsh or bash (macOS and Linux) |
| --- | --- | --- |
| Print working directory | `Get-Location` (alias `pwd`) | `pwd` |
| Change directory | `Set-Location folder` (alias `cd`) | `cd folder` |
| List files | `Get-ChildItem` (aliases `ls`, `dir`) | `ls` or `ls -la` |
| Make a folder | `New-Item -ItemType Directory name` (alias `mkdir`) | `mkdir name` |
| Remove a file | `Remove-Item file.txt` | `rm file.txt` |
| Remove a folder and contents | `Remove-Item -Recurse -Force name` | `rm -r name` |
| Create an empty file | `New-Item file.txt` | `touch file.txt` |
| Copy | `Copy-Item a.txt b.txt` | `cp a.txt b.txt` |
| Move or rename | `Move-Item a.txt b.txt` | `mv a.txt b.txt` |
| Show file contents | `Get-Content file.txt` | `cat file.txt` |
| Clear the screen | `Clear-Host` (alias `cls`) | `clear` |

## File Paths

A path describes where a file or folder lives.

- Absolute path: starts from the root of the file system and works from anywhere.
  - Windows: `C:\Users\amina\projects\notes`
  - macOS: `/Users/amina/projects/notes`
  - Linux: `/home/amina/projects/notes`
- Relative path: starts from the current working directory and changes meaning depending on where you are.
  - `src/app` means "the app folder inside src, inside the folder I am in now".

Special path symbols:

| Symbol | Meaning |
| --- | --- |
| `.` | The current directory |
| `..` | The parent directory |
| `~` | Your home directory |

Rules to remember:

- Windows uses backslashes (`\`). macOS and Linux use forward slashes (`/`). PowerShell and Python accept forward slashes on Windows as well.
- Wrap paths that contain spaces in quotes: `cd "My Projects"`.
- Linux file systems are case-sensitive, so `Config.py` and `config.py` are different files. Windows and default macOS volumes are not case-sensitive. Code that works on a laptop can fail on a Linux server because of this.

## Basic Examples

A short session on macOS or Linux:

```bash
pwd
mkdir python-notes
cd python-notes
mkdir src
ls
cd ..
rm -r python-notes
```

The same session in Windows PowerShell:

```powershell
Get-Location
New-Item -ItemType Directory python-notes
Set-Location python-notes
New-Item -ItemType Directory src
Get-ChildItem
Set-Location ..
Remove-Item -Recurse -Force python-notes
```

Asking Python where it is currently running:

```python
from pathlib import Path

print(Path.cwd())
```

## Backend Industry Example

Backend programs are started by tools you do not control: a process manager, a scheduled job, a container runtime. They are rarely started from the folder you expect. If your code uses a relative path such as `"config/settings.toml"`, it resolves against the current working directory and breaks as soon as the starting directory changes.

The production pattern is to build paths from the location of the source file itself.

```python
from pathlib import Path

# This file lives at <project_root>/src/orders_service/paths.py
BASE_DIR = Path(__file__).resolve().parents[2]
CONFIG_DIR = BASE_DIR / "config"
SETTINGS_FILE = CONFIG_DIR / "settings.toml"


def get_settings_path() -> Path:
    """Return the settings file path or fail with a clear message."""
    if not SETTINGS_FILE.is_file():
        raise FileNotFoundError(f"Settings file not found: {SETTINGS_FILE}")
    return SETTINGS_FILE
```

`Path(__file__)` is the location of the current file, `resolve()` turns it into an absolute path, and `parents[2]` walks up two levels to the project root. The result is the same no matter which directory the program was launched from.

## Common Mistakes

- Running `rm -r` or `Remove-Item -Recurse -Force` in the wrong directory. Deleted files do not go to a recycle bin. Run `pwd` and `ls` first.
- Assuming the working directory is the project folder when a program is started by another tool.
- Forgetting quotes around paths with spaces.
- Ignoring case sensitivity and discovering the bug only after deploying to Linux.
- Confusing the terminal with the shell when searching for help. Command syntax depends on the shell, not the terminal window.

## Summary

Python compiles source to bytecode and interprets it, so you run source files directly. The terminal is the window and the shell is the command interpreter inside it. Learn the core navigation and file commands in PowerShell, zsh, and bash, and understand the difference between absolute and relative paths. In production code, resolve paths from `__file__` instead of trusting the current working directory.
