# 1.2 Variables and Objects

## Overview

In Python, a variable is not a box that holds a value. A variable is a name that refers to an object stored in memory. Almost every confusing Python bug involving shared data comes from not understanding this one idea.

## Names and Objects

Every value in Python is an object. It has an identity (where it lives), a type, and a value. Assignment with `=` binds a name to an object.

```python
a = [1, 2, 3]
b = a
```

Here there is one list and two names that refer to it. `b = a` does not copy the list.

```python
b.append(4)
print(a)   # [1, 2, 3, 4]
```

## Assignment Forms

```python
x = 10                 # simple assignment
a = b = 0              # both names refer to the same object
width, height = 4, 5   # unpacking: width is 4, height is 5
a, b = b, a            # swap two names
count = 1
count += 1             # augmented assignment, same as count = count + 1
```

## Dynamic Typing

A name has no fixed type. The object has the type. The same name can later refer to an object of a different type.

```python
value = 42
print(type(value))     # <class 'int'>
value = "forty-two"
print(type(value))     # <class 'str'>
```

Python is dynamically typed but also strongly typed. It does not silently convert between unrelated types.

```python
"5" + 3    # TypeError: can only concatenate str (not "int") to str
```

## `id()` and `type()`

- `id(obj)` returns a number identifying the object. In CPython it is related to the object's memory address.
- `type(obj)` returns the object's class.
- `isinstance(obj, int)` checks whether an object is of a type and is usually the better choice in real code.

```python
a = [1, 2]
b = a
c = [1, 2]
print(id(a) == id(b))   # True: same object
print(id(a) == id(c))   # False: equal contents, different objects
```

## Mutability and Immutability

An immutable object cannot be changed after creation. A mutable object can.

| Immutable | Mutable |
| --- | --- |
| `int`, `float`, `bool`, `complex` | `list` |
| `str`, `bytes` | `dict` |
| `tuple`, `frozenset` | `set` |
| `None` | most user-defined class instances |

```python
name = "amina"
name[0] = "A"          # TypeError: 'str' object does not support item assignment
name = "A" + name[1:]  # correct: build a new string and rebind the name
```

Operations on immutable objects create new objects. Operations on mutable objects can change them in place, and every name referring to that object sees the change.

```python
a = [1]
b = a
a += [2]               # list += modifies the existing list
print(b)               # [1, 2]

x = 1
y = x
x += 1                 # int cannot be modified; x now refers to a new object
print(y)               # 1
```

## `is` vs. `==`

- `==` asks whether two objects have equal values.
- `is` asks whether two names refer to the exact same object.

```python
a = [1, 2]
b = [1, 2]
print(a == b)   # True
print(a is b)   # False
```

Use `is` only for singletons, mainly `None`, `True`, and `False`. Do not use `is` to compare numbers or strings. CPython happens to reuse small integers and some strings, which makes `is` appear to work and then fail unpredictably.

## None

`None` is a special object meaning "no value". It is the only instance of `NoneType`. Functions that do not return anything return `None`. Always test for it with `is None` or `is not None`.

```python
result = None
if result is None:
    print("nothing yet")
```

## Naming Rules

- Names may contain letters, digits, and underscores and cannot start with a digit.
- Names are case-sensitive: `total`, `Total`, and `TOTAL` are different.
- Reserved words such as `if`, `for`, `class`, `return`, and `None` cannot be used. `import keyword; print(keyword.kwlist)` lists them.
- Do not reuse built-in names such as `list`, `dict`, `str`, `id`, `type`, `input`, or `sum`. Doing so hides the built-in for the rest of the scope.
- A single leading underscore signals "internal use". A lone `_` is conventionally a throwaway value.

## Basic Examples

```python
price = 19.99
quantity = 3
total = price * quantity
print(total)

first = "Amina"
last = "Rahman"
full_name = first + " " + last
print(full_name, type(full_name))
```

Seeing aliasing and copying side by side:

```python
original = [1, 2, 3]
alias = original          # same object
copy = original.copy()    # new list with the same contents

original.append(99)
print(alias)   # [1, 2, 3, 99]
print(copy)    # [1, 2, 3]
```

## Backend Industry Example

Two patterns that prevent common production bugs.

First, distinguish "no value given" from "a falsy value given". A page size of `0` is a real (if invalid) input, different from the parameter being missing. Using `is None` keeps that difference.

```python
DEFAULT_PAGE_SIZE = 20
MAX_PAGE_SIZE = 100


def resolve_page_size(requested: int | None) -> int:
    """Return a safe page size for a paginated API endpoint."""
    if requested is None:
        return DEFAULT_PAGE_SIZE
    return max(1, min(requested, MAX_PAGE_SIZE))
```

Writing `if not requested:` instead would treat `0` the same as a missing value and hide the client's mistake.

Second, never mutate a shared default through an alias. Module-level configuration is shared by every request.

```python
DEFAULT_HEADERS = {"Accept": "application/json", "User-Agent": "orders-service"}


def build_headers(token: str) -> dict[str, str]:
    """Return request headers for one outbound call."""
    headers = DEFAULT_HEADERS.copy()      # work on a copy, not the shared dict
    headers["Authorization"] = f"Bearer {token}"
    return headers
```

Without `.copy()`, the first call would write the user's token into `DEFAULT_HEADERS`, and every later request would leak that token.

## Common Mistakes

- Believing `b = a` copies a list or dictionary.
- Comparing with `is` when `==` is meant, especially for numbers and strings.
- Writing `== None` instead of `is None`.
- Shadowing built-ins, for example `list = [1, 2, 3]` and then failing on `list("abc")`.
- Using `if not value:` when `0`, an empty string, or an empty list is a valid input.

## Summary

Names refer to objects. Assignment binds a name and never copies. Immutable objects are replaced when changed, mutable objects are modified in place and shared by every name referring to them. Use `==` for value equality and `is` only for `None` and other singletons. Choose names that follow the rules and never shadow built-ins.
