# 1.5 Input and Output

## Overview

A program reads data from somewhere and writes results somewhere else. For command-line programs the default input is the keyboard (or a pipe from another program) and the default output is the terminal. This module covers `print`, `input`, reading standard input, and the difference between standard output and standard error.

## print()

```python
print("Hello")                   # Hello
print("a", "b", "c")             # a b c
print("a", "b", "c", sep="-")    # a-b-c
print("loading", end="")         # no newline after the text
print(" done")                   # loading done
```

Parameters:

| Parameter | Default | Purpose |
| --- | --- | --- |
| `*objects` | none | Values to print, converted to strings |
| `sep` | `" "` | Text placed between values |
| `end` | `"\n"` | Text placed after the last value |
| `file` | `sys.stdout` | Where to write |
| `flush` | `False` | Force the text out immediately instead of buffering |

`print` accepts any number of arguments of any type and calls `str()` on each.

## input()

`input(prompt)` shows the prompt, waits for the user to press Enter, and returns what was typed as a string. It always returns `str`, even if the user typed digits.

```python
name = input("Your name: ")
print(f"Hello, {name}")
```

## Type Conversion

Convert input explicitly with `int()`, `float()`, and similar functions. They raise `ValueError` if the text is not valid.

```python
age_text = input("Age: ")
age = int(age_text)
print(f"In ten years you will be {age + 10}")
```

Handling bad input:

```python
while True:
    text = input("Enter a whole number: ")
    try:
        number = int(text)
        break
    except ValueError:
        print("That is not a whole number, try again.")
print(f"You entered {number}")
```

Useful conversions: `int("42")`, `float("3.5")`, `str(42)`, `bool(0)`, `list("abc")`. `int("3.5")` fails; use `int(float("3.5"))`.

## Formatted Output

f-strings and format specifications give control over how values are displayed.

```python
item = "Notebook"
price = 149.5
print(f"{item:<12} {price:>8.2f}")
print(f"Total: {price * 3:,.2f}")
```

## Reading from Standard Input

Every process has three standard streams:

| Stream | Name | Default |
| --- | --- | --- |
| Standard input | `sys.stdin` | keyboard or piped data |
| Standard output | `sys.stdout` | terminal |
| Standard error | `sys.stderr` | terminal |

```python
import sys

first_line = sys.stdin.readline()   # one line, includes the trailing newline
rest = sys.stdin.read()             # everything remaining

for line in sys.stdin:              # iterate line by line, memory friendly
    print(line.strip())
```

Data can be piped into a program from another command or from a file:

```bash
echo "hello" | python read_stdin.py
python read_stdin.py < input.txt
```

PowerShell can pipe a list of strings, one per line:

```powershell
"10.50", "4.25" | python sum_amounts.py
```

When no data is provided and input is closed, `input()` raises `EOFError`.

## Standard Output versus Standard Error

Results go to standard output. Diagnostics and error messages go to standard error. They can then be redirected separately.

```python
import sys

print("result data")
print("something went wrong", file=sys.stderr)
```

```bash
python script.py > output.txt 2> errors.txt
```

## Basic Examples

A small calculator:

```python
a = float(input("First number: "))
b = float(input("Second number: "))
print(f"Sum: {a + b}")
print(f"Product: {a * b}")
```

A menu using `end` and `sep`:

```python
options = ["start", "stop", "status"]
for number, option in enumerate(options, start=1):
    print(number, option, sep=". ")
```

## Backend Industry Example

A command-line filter program that reads values from standard input, writes the result to standard output, reports bad lines on standard error, and returns an exit code. This is how small tools are chained in shell scripts and data jobs.

```python
# sum_amounts.py
import sys
from decimal import Decimal, InvalidOperation


def main() -> int:
    total = Decimal("0")
    invalid_lines = 0

    for line_number, line in enumerate(sys.stdin, start=1):
        text = line.strip()
        if not text:
            continue
        try:
            total += Decimal(text)
        except InvalidOperation:
            invalid_lines += 1
            print(f"line {line_number}: not a number: {text!r}", file=sys.stderr)

    print(f"total={total}")
    return 1 if invalid_lines else 0


if __name__ == "__main__":
    raise SystemExit(main())
```

Run it:

```bash
printf "10.50\n4.25\nabc\n" | python sum_amounts.py
```

Standard output receives `total=14.75`, standard error receives `line 3: not a number: 'abc'`, and the exit code is `1` so a calling script knows that some input was rejected.

Services that run continuously use the `logging` module for diagnostics instead of `print`, because logging adds timestamps, severity levels, and configurable destinations. `print` remains the right tool for command-line programs that produce output.

## Common Mistakes

- Forgetting that `input()` returns a string and trying to do arithmetic on it.
- Not handling `ValueError` when converting user input.
- Writing error messages to standard output, which pollutes data that other programs consume.
- Forgetting the trailing newline in lines read from standard input; use `strip()` or `rstrip("\n")`.
- Using `input()` in code that runs without a terminal, such as a service or a scheduled job.
- Reading a huge file with `sys.stdin.read()` instead of iterating line by line.

## Summary

`print` writes to standard output and is controlled with `sep`, `end`, `file`, and `flush`. `input` reads a line and returns a string that must be converted explicitly. Standard input, output, and error are separate streams: send data to output and diagnostics to error, read input line by line, and return an exit code that tells the caller whether the program succeeded.
