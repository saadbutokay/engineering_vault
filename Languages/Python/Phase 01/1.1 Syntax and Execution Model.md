# 1.1 Syntax and Execution Model

## Overview

Syntax is the set of rules that decides whether text is a valid Python program. The execution model describes what Python does with that text when you run it. Understanding both explains why Python reports certain errors where it does and why the order of your code matters.

## Indentation

Python uses indentation, not braces, to mark where a block of code begins and ends. A line ending in a colon opens a block, and the lines inside it are indented by the same amount. The standard is 4 spaces.

```python
if True:
    print("inside the block")
    print("still inside")
print("outside the block")
```

Rules:

- Every line in one block must use the same indentation.
- Do not mix tabs and spaces. Configure your editor to insert spaces.
- A block needs at least one statement. Use `pass` as a placeholder that does nothing.
- Wrong indentation raises `IndentationError`.

## Comments

A comment starts with `#` and continues to the end of the line. Python ignores it.

```python
# This whole line is a comment
price = 20  # This is a comment after code
```

Python has no block comment syntax. Use several `#` lines. A string placed as the first statement of a module, class, or function is a docstring, which is documentation rather than a comment. Good comments explain why something is done, not what the code already says.

## Statements and Expressions

- An expression produces a value. Examples: `2 + 3`, `len(name)`, `price * quantity`, `"a" if flag else "b"`.
- A statement performs an action. Examples: assignment (`x = 5`), `if`, `for`, `while`, `return`, `import`, `def`.

An expression can appear wherever a value is needed, for example inside a function call. A statement cannot.

```python
total = 2 + 3          # statement that contains an expression
print(len("hello"))    # the expression len("hello") is the argument
```

## Line Continuation

A statement normally ends at the end of the line. For long statements there are two ways to continue.

Implicit continuation inside `()`, `[]`, or `{}`. This is the preferred style.

```python
total = (
    base_price
    + shipping_cost
    + tax_amount
)

colors = [
    "red",
    "green",
    "blue",
]
```

Explicit continuation with a backslash at the end of the line. It is fragile, because any character after the backslash breaks it, so avoid it when brackets will do.

```python
total = base_price + \
    shipping_cost
```

A semicolon can put two statements on one line (`a = 1; b = 2`). Avoid it. One statement per line is the standard.

## How Python Runs Code

1. Source: you write text in a `.py` file.
2. Compilation: when the program starts, Python parses the source and compiles it into bytecode, a compact set of low-level instructions. Syntax errors are found at this step, before any line runs.
3. Execution: the Python virtual machine, part of the interpreter, executes the bytecode one instruction at a time, from top to bottom.

For imported modules, Python saves the bytecode in a `__pycache__` folder as `.pyc` files so it can skip recompiling next time. The main script you run is compiled each time.

Consequences worth knowing:

- Syntax errors stop the whole file before anything runs. Name errors and type errors appear only when the faulty line is reached.
- A `def` statement is executed when Python reaches it. It creates a function object. The body of the function does not run until the function is called.
- Names are looked up while the program runs, so a function may refer to a name defined later in the file, as long as that name exists by the time the function is called.

You can inspect bytecode with the `dis` module:

```python
import dis


def add(a, b):
    return a + b


dis.dis(add)
```

## Basic Examples

A function defined before it is called:

```python
def greet(name):
    print(f"Hello, {name}!")


greet("Amina")
```

Calling before the definition fails, because the `def` statement has not been executed yet:

```python
greet("Amina")   # NameError: name 'greet' is not defined


def greet(name):
    print(f"Hello, {name}!")
```

The body is not checked until called:

```python
def broken():
    return undefined_name   # no error yet


print("program is running")  # prints normally
broken()                     # NameError happens here
```

## Backend Industry Example

A small module showing the conventions used in real services: a module docstring, constants at the top, a long condition split inside parentheses, and a comment that explains why instead of what.

```python
"""Retry policy for outbound payment gateway calls."""

RETRYABLE_STATUS_CODES = {429, 502, 503, 504}
MAX_ATTEMPTS = 5


def should_retry(status_code: int, attempt: int, is_idempotent: bool) -> bool:
    """Decide whether a failed gateway call may be retried."""
    # Retrying a non-idempotent call could charge a customer twice,
    # so it is only allowed when the request is safe to repeat.
    return (
        attempt < MAX_ATTEMPTS
        and is_idempotent
        and status_code in RETRYABLE_STATUS_CODES
    )
```

The parentheses allow each condition to sit on its own line, which makes the business rule readable and each condition easy to change in a code review.

## Common Mistakes

- Mixing tabs and spaces and getting `IndentationError` or `TabError`.
- Forgetting the colon at the end of `if`, `for`, `def`, and similar lines.
- Calling a function before the `def` statement has run.
- Assuming a function body is checked for mistakes when it is defined. Errors inside it appear only when it is called.
- Using backslash continuation with trailing spaces after the backslash.

## Summary

Indentation defines blocks, and a colon opens them. Expressions produce values and statements perform actions. Prefer brackets for line continuation. Python compiles source to bytecode and then executes it top to bottom, so syntax errors appear immediately while most other errors appear only when the faulty line runs.
