# 3.2 Arguments

## Overview

Python offers several ways to pass values into a function: by position, by name, with defaults, and with variable-length argument lists. Good use of these features produces functions that are easy to call correctly and hard to call incorrectly.

## Positional and Keyword Arguments

```python
def create_user(name, age, active):
    return {"name": name, "age": age, "active": active}

create_user("Amina", 31, True)                      # positional: order matters
create_user(name="Amina", age=31, active=True)      # keyword: order does not matter
create_user("Amina", active=True, age=31)           # mixed: positional first
```

Positional arguments must come before keyword arguments in a call. Passing the same parameter twice, or a name that does not exist, raises `TypeError`:

```text
create_user() missing 1 required positional argument: 'active'
create_user() takes 3 positional arguments but 4 were given
create_user() got an unexpected keyword argument 'nme'
create_user() got multiple values for argument 'name'
```

Keyword arguments make calls self-explanatory, especially for booleans. `create_user("Amina", 31, True)` is less readable than the keyword form.

## Default Values

A parameter with a default becomes optional.

```python
def connect(host, port=5432, timeout=5.0):
    return f"{host}:{port} (timeout {timeout}s)"

print(connect("db.example.com"))                 # db.example.com:5432 (timeout 5.0s)
print(connect("db.example.com", timeout=10))     # db.example.com:5432 (timeout 10s)
```

Parameters with defaults must come after those without: `def f(a=1, b)` is a syntax error.

## The Mutable Default Argument Pitfall

Default values are created once, when the function is defined, not each time it is called. A mutable default is therefore shared by every call.

```python
def add_item(item, items=[]):
    items.append(item)
    return items

print(add_item("a"))    # ['a']
print(add_item("b"))    # ['a', 'b']   the same list is reused
```

The standard fix is to use `None` as the default and create the mutable object inside the function:

```python
def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

Immutable defaults such as numbers, strings, tuples, `None`, and `True` are safe.

## *args: Variable Positional Arguments

`*args` collects any extra positional arguments into a tuple.

```python
def total(*numbers):
    return sum(numbers)

print(total(1, 2, 3))       # 6
print(total())              # 0

def show(first, *others):
    print(first, others)

show(1, 2, 3)               # 1 (2, 3)
```

The name `args` is a convention. What matters is the star.

## **kwargs: Variable Keyword Arguments

`**kwargs` collects extra keyword arguments into a dictionary.

```python
def describe(**details):
    for key, value in details.items():
        print(f"{key} = {value}")

describe(name="Amina", city="Chattogram")
# name = Amina
# city = Chattogram
```

## Positional-Only and Keyword-Only Parameters

A `/` in the parameter list means everything before it can only be passed by position. A `*` means everything after it can only be passed by keyword.

```python
def example(a, b, /, c, *, d):
    return a, b, c, d

example(1, 2, 3, d=4)        # fine
example(1, 2, c=3, d=4)      # fine: c may be positional or keyword
example(1, 2, 3, 4)          # TypeError: d is keyword-only
example(a=1, b=2, c=3, d=4)  # TypeError: a and b are positional-only
```

Why use them:

- Keyword-only parameters force readable calls for options and flags: `fetch(url, retries=3)` instead of `fetch(url, 3)`.
- Positional-only parameters keep names free to change later without breaking callers.

The full order of a signature is: positional-only, `/`, normal parameters, `*args` (or a bare `*`), keyword-only parameters, `**kwargs`.

## Argument Unpacking at Call Sites

The same stars work in reverse when calling a function.

```python
def connect(host, port, timeout):
    return f"{host}:{port}/{timeout}"

values = ["db.example.com", 5432, 5.0]
print(connect(*values))      # a list or tuple becomes positional arguments

options = {"host": "db.example.com", "port": 5432, "timeout": 5.0}
print(connect(**options))    # a dictionary becomes keyword arguments

print(*[1, 2, 3], sep="-")   # 1-2-3
```

This is also how a function passes along whatever it received to another function.

```python
def logged_call(func, *args, **kwargs):
    print(f"calling {func.__name__}")
    return func(*args, **kwargs)
```

## Basic Examples

```python
def power(base, exponent=2):
    return base ** exponent

print(power(5))         # 25
print(power(2, 10))     # 1024
print(power(exponent=3, base=2))   # 8

def average(*numbers):
    return sum(numbers) / len(numbers)

print(average(80, 90, 100))        # 90.0
```

## Backend Industry Example

A function that builds an outbound HTTP request description. It shows positional-only arguments for the stable core, keyword-only options with safe defaults, `None` instead of a mutable default, and `**query_params` for open-ended extras.

```python
def build_request(
    method: str,
    url: str,
    /,
    *,
    timeout: float = 5.0,
    headers: dict[str, str] | None = None,
    **query_params: str,
) -> dict:
    """Describe an outbound HTTP request.

    Args:
        method: The HTTP method, for example "get".
        url: The target URL.
        timeout: Seconds to wait before giving up.
        headers: Extra headers merged over the defaults.
        **query_params: Any further keyword arguments become query parameters.
    """
    merged_headers = {"Accept": "application/json"} | (headers or {})
    return {
        "method": method.upper(),
        "url": url,
        "timeout": timeout,
        "headers": merged_headers,
        "params": query_params,
    }


request = build_request(
    "get",
    "https://api.example.com/orders",
    timeout=10.0,
    headers={"Authorization": "Bearer token"},
    status="paid",
    page="2",
)
print(request)
```

`build_request("get", url, 10.0)` would be rejected because `timeout` is keyword-only, so a call can never be misread. Nothing is shared between calls because `headers` defaults to `None`, and the merge with `|` creates a new dictionary each time.

## Common Mistakes

- Using a list, dictionary, or set as a default value.
- Putting a parameter with a default before one without.
- Passing booleans positionally so the call cannot be understood without reading the definition.
- Accepting `**kwargs` and silently ignoring typos in the argument names.
- Expecting `*args` to be a list. It is a tuple.
- Confusing `*` in a definition (collecting arguments) with `*` in a call (spreading them out).

## Summary

Pass arguments by position or by name, give optional parameters defaults, and never use a mutable default; use `None` instead. Use `*args` and `**kwargs` to accept variable input, `/` and `*` to restrict how parameters can be passed, and the same stars at call sites to unpack collections into arguments. Keyword-only options with safe defaults make APIs hard to misuse.
