# 3.5 Closures

## Overview

A closure is a function that remembers the variables from the scope where it was created, even after that scope has finished running. Closures let you build functions that carry their own configuration or state without using classes or global variables.

## Nested Functions and Free Variables

A function can be defined inside another function. If the inner function uses a name from the outer function that it does not define itself, that name is a free variable.

```python
def outer():
    message = "hello"

    def inner():
        print(message)     # message is a free variable

    return inner

greeter = outer()
greeter()                  # hello, even though outer() has already finished
```

`greeter` is a closure. It keeps `message` alive.

## Function Factories

A function that builds and returns other functions is called a function factory.

```python
def make_multiplier(factor):
    def multiply(number):
        return number * factor
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(10))     # 20
print(triple(10))     # 30
```

`double` and `triple` are two separate closures, each holding its own `factor`.

You can inspect what a closure captured:

```python
print(double.__closure__[0].cell_contents)    # 2
```

## State Capture with nonlocal

A closure can read free variables freely. To rebind one, declare it `nonlocal`.

```python
def make_counter():
    count = 0

    def counter():
        nonlocal count
        count += 1
        return count

    return counter

first = make_counter()
second = make_counter()
print(first(), first(), first())    # 1 2 3
print(second())                     # 1, independent state
```

Mutating a captured mutable object (calling `append` on a captured list, for example) does not need `nonlocal`, because the name is not rebound.

## The Late-Binding Pitfall

A closure captures the variable, not its value at that moment. The value is looked up when the function is called.

```python
functions = [lambda: i for i in range(3)]
print([f() for f in functions])     # [2, 2, 2], not [0, 1, 2]
```

All three lambdas share the same `i`, which ends the loop at 2. Two common fixes:

```python
# Fix 1: bind the current value as a default argument
functions = [lambda i=i: i for i in range(3)]
print([f() for f in functions])     # [0, 1, 2]

# Fix 2: create each function through a factory so each has its own variable
def make_returner(value):
    return lambda: value

functions = [make_returner(i) for i in range(3)]
print([f() for f in functions])     # [0, 1, 2]
```

## Closures versus Classes

A closure with one function and a little state is a lighter alternative to a class. When the state grows or several operations share it, a class is clearer. Choose the simpler tool that stays readable.

## Basic Examples

```python
def make_greeter(greeting):
    def greet(name):
        return f"{greeting}, {name}!"
    return greet

hello = make_greeter("Hello")
salam = make_greeter("Assalamu alaikum")
print(hello("Amina"))     # Hello, Amina!
print(salam("Bilal"))     # Assalamu alaikum, Bilal!

def make_accumulator():
    values = []
    def add(value):
        values.append(value)
        return sum(values)
    return add

acc = make_accumulator()
print(acc(10), acc(5), acc(1))    # 10 15 16
```

## Backend Industry Example

A rate limiter built as a closure, and a validator factory. The limiter takes a clock function as a parameter, so tests can supply fake time instead of waiting.

```python
import time
from collections import deque
from collections.abc import Callable


def make_rate_limiter(
    max_calls: int, period: float, clock: Callable[[], float] = time.monotonic
) -> Callable[[], bool]:
    """Return a function that says whether another call is allowed right now."""
    calls: deque[float] = deque()      # captured state

    def allow() -> bool:
        now = clock()
        while calls and calls[0] <= now - period:
            calls.popleft()
        if len(calls) >= max_calls:
            return False
        calls.append(now)
        return True

    return allow


# Test with a fake clock that returns scripted times
fake_times = iter([0.0, 1.0, 2.0, 3.0, 11.0])
allow_request = make_rate_limiter(
    max_calls=3, period=10.0, clock=lambda: next(fake_times)
)
print([allow_request() for _ in range(5)])    # [True, True, True, False, True]


def make_length_validator(minimum: int, maximum: int) -> Callable[[str], bool]:
    """Return a function that checks text length against fixed limits."""
    def is_valid(text: str) -> bool:
        return minimum <= len(text) <= maximum
    return is_valid


is_valid_username = make_length_validator(3, 20)
is_valid_password = make_length_validator(12, 128)
print(is_valid_username("amina"), is_valid_password("short"))    # True False
```

`calls` is mutated but never rebound, so `allow` does not need `nonlocal`. Each limiter created by `make_rate_limiter` has its own queue, so one limiter can be created per user or per API key.

The late-binding bug appears in real code when handlers are registered in a loop:

```python
def send(channel: str) -> str:
    return f"sending to {channel}"


channels = ["email", "sms", "push"]

buggy = {name: (lambda: send(name)) for name in channels}
print(buggy["email"]())       # sending to push  (wrong)

fixed = {name: (lambda name=name: send(name)) for name in channels}
print(fixed["email"]())       # sending to email
```

## Common Mistakes

- Expecting a closure to capture the value instead of the variable in a loop.
- Trying to modify a captured variable without `nonlocal`, which creates `UnboundLocalError`.
- Creating deeply nested functions that are hard to read.
- Using a closure to hold large, growing state that would be clearer in a class.
- Forgetting that every call to the factory creates a separate, independent state.

## Summary

A closure is an inner function that remembers variables from its enclosing function. Function factories use closures to produce configured functions, and `nonlocal` lets a closure update captured state. Closures capture variables, not values, so loop-created functions need an explicit binding. Use closures for small, self-contained behaviour and classes when the state and operations grow.
