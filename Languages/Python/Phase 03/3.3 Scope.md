# 3.3 Scope

## Overview

Scope decides where a name can be seen. A name defined inside a function is not visible outside it, and a function can read names defined outside it. Python resolves names by a fixed lookup order called the LEGB rule. Understanding it explains many `NameError` and `UnboundLocalError` surprises.

## The LEGB Rule

When Python meets a name, it searches four scopes in order and uses the first match.

| Letter | Scope | Where it lives |
| --- | --- | --- |
| L | Local | names assigned inside the current function |
| E | Enclosing | names in any outer function that contains the current one |
| G | Global | names at the top level of the module |
| B | Built-in | names Python provides, such as `len`, `print`, and `range` |

```python
x = "global"

def outer():
    x = "enclosing"

    def inner():
        x = "local"
        print(x)       # local

    inner()
    print(x)           # enclosing

outer()
print(x)               # global
```

Each `x` is a different variable in a different scope.

## Local Scope

Variables assigned inside a function exist only while it runs.

```python
def calculate():
    result = 10 * 5
    return result

calculate()
print(result)          # NameError: name 'result' is not defined
```

Reading a global from inside a function works without any special syntax:

```python
TAX_RATE = 0.075

def add_tax(price):
    return price * (1 + TAX_RATE)
```

## Assignment Creates a Local Name

If a function assigns to a name anywhere in its body, Python treats that name as local for the entire function. Reading it before the assignment then fails.

```python
count = 0

def increment():
    count = count + 1      # UnboundLocalError

increment()
```

```text
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value
```

The right side tries to read the local `count`, which has no value yet. Older Python versions word this as "local variable 'count' referenced before assignment".

## global and nonlocal

`global` lets a function rebind a module-level name.

```python
count = 0

def increment():
    global count
    count += 1

increment()
increment()
print(count)           # 2
```

`nonlocal` lets an inner function rebind a name from the enclosing function.

```python
def make_counter():
    total = 0

    def add(amount):
        nonlocal total
        total += amount
        return total

    return add

counter = make_counter()
print(counter(5))      # 5
print(counter(3))      # 8
```

Neither keyword is needed to modify a mutable object. `items.append(1)` mutates the object and does not rebind the name, so it works without `global`. Only assignment (`=`, `+=` on numbers and strings) rebinds.

## Why to Avoid Global State

Modifying module-level variables from inside functions looks convenient but causes problems:

- Hidden dependencies: reading the function signature does not reveal what it depends on or changes.
- Hard to test: tests share the global, so one test can break another, and you must remember to reset it.
- Unpredictable under concurrency: two threads or requests can change the same value at the same time.
- Hard to reuse: a function tied to a global cannot easily be used in two contexts at once.

Prefer passing data in as parameters and getting results back as return values. Module-level constants (`MAX_RETRIES = 3`, `TAX_RATE`) that are never changed are fine and normal.

## Other Scope Facts

```python
for i in range(3):
    pass
print(i)                     # 2: loop variables stay in the enclosing scope

squares = [n * n for n in range(3)]
print(n)                     # NameError: comprehension variables do not leak

list = [1, 2, 3]            # shadows the built-in list
list("abc")                  # TypeError: 'list' object is not callable
```

## Basic Examples

```python
message = "outside"

def show():
    message = "inside"
    print(message)

show()                  # inside
print(message)          # outside: the function's message was a separate variable

def add_to_total(total, amount):
    return total + amount

running = 0
running = add_to_total(running, 10)
running = add_to_total(running, 5)
print(running)          # 15
```

## Backend Industry Example

A request counter written with global state, and the same logic with explicit state. The second version can be tested without leftovers and used by several independent components.

```python
# Global state: hidden dependency and shared between every test and thread
_request_count = 0


def handle_request_global() -> int:
    global _request_count
    _request_count += 1
    return _request_count


# Explicit state: the caller owns the data and passes it in
def handle_request(metrics: dict[str, int]) -> int:
    """Count one request in the given metrics store and return the new total."""
    metrics["requests"] = metrics.get("requests", 0) + 1
    return metrics["requests"]


metrics_for_api: dict[str, int] = {}
metrics_for_tests: dict[str, int] = {}

handle_request(metrics_for_api)
handle_request(metrics_for_api)
handle_request(metrics_for_tests)

print(metrics_for_api)      # {'requests': 2}
print(metrics_for_tests)    # {'requests': 1}
```

Two independent counters exist at the same time, and a unit test creates a fresh dictionary instead of resetting a global. Module-level constants remain the right tool for fixed configuration:

```python
MAX_PAGE_SIZE = 100
DEFAULT_TIMEOUT_SECONDS = 5.0
```

## Common Mistakes

- Assigning to a variable inside a function and expecting it to change the global one.
- Getting `UnboundLocalError` by reading a name that is also assigned later in the same function.
- Using `global` to share state between functions instead of passing parameters.
- Shadowing built-ins such as `list`, `id`, `type`, and `input`.
- Assuming a variable defined inside an `if` or `for` block is private to that block. Python has no block scope, only function scope.

## Summary

Names are looked up in the local, enclosing, global, and built-in scopes, in that order. Assigning to a name inside a function makes it local unless declared `global` or `nonlocal`. Treat global variables that change as a last resort and pass state through parameters and return values instead. Constants at module level are fine.
