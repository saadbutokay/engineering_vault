# 3.6 Decorators

## Overview

A decorator is a function that takes a function and returns a function, usually adding behaviour around the original without changing its code. Decorators are used for logging, timing, retrying, access control, caching, and registering functions. Web frameworks use them heavily.

## The Idea

Because functions are objects and closures remember their surroundings, you can write a function that wraps another function:

```python
def shout(func):
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        return result.upper()
    return wrapper

def greet(name):
    return f"hello, {name}"

greet = shout(greet)          # replace greet with the wrapped version
print(greet("amina"))         # HELLO, AMINA
```

The `@` syntax is shorthand for exactly that reassignment.

```python
@shout
def greet(name):
    return f"hello, {name}"
```

`@shout` above `def greet` means `greet = shout(greet)`.

## Anatomy of a Decorator

```python
def log_calls(func):
    def wrapper(*args, **kwargs):
        print(f"calling {func.__name__}")
        result = func(*args, **kwargs)
        print(f"{func.__name__} returned {result!r}")
        return result
    return wrapper

@log_calls
def add(a, b):
    return a + b

add(2, 3)
# calling add
# add returned 5
```

Three rules for a well-behaved decorator:

- Accept any arguments with `*args, **kwargs` and pass them through, so it works with any function.
- Return the wrapped function's result.
- Preserve the original function's identity with `functools.wraps`, described next.

## functools.wraps

Without it the decorated function loses its name and docstring, because the name `add` now points at `wrapper`.

```python
@log_calls
def add(a, b):
    """Add two numbers."""
    return a + b

print(add.__name__)    # wrapper
print(add.__doc__)     # None
```

This breaks debugging, logs, and documentation tools. `functools.wraps` copies the original's metadata onto the wrapper.

```python
import functools

def log_calls(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"calling {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@log_calls
def add(a, b):
    """Add two numbers."""
    return a + b

print(add.__name__)    # add
print(add.__doc__)     # Add two numbers.
```

Always use `@functools.wraps(func)` in your decorators.

## Decorators with Arguments

To give a decorator settings, add one more level. The outer function receives the settings and returns the actual decorator.

```python
import functools

def repeat(times):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            result = None
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(times=3)
def say(message):
    print(message)

say("hi")      # prints hi three times
```

`@repeat(times=3)` first calls `repeat(times=3)`, which returns `decorator`, and then applies that to `say`. Parentheses are required even when every argument has a default. Writing `@repeat` instead of `@repeat()` passes the function in as `times`, which is a classic mistake.

## Stacking Decorators

Several decorators can be applied to one function. They are applied from the bottom up, closest to the function first, but at call time the outermost wrapper runs first.

```python
def tag(name):
    def decorator(func):
        def wrapper(*args, **kwargs):
            print(f"enter {name}")
            result = func(*args, **kwargs)
            print(f"exit {name}")
            return result
        return wrapper
    return decorator

@tag("outer")
@tag("inner")
def work():
    print("working")

work()
# enter outer
# enter inner
# working
# exit inner
# exit outer
```

This is equivalent to `work = tag("outer")(tag("inner")(work))`.

## Basic Examples

A timing decorator:

```python
import functools
import time

def timed(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            elapsed = time.perf_counter() - start
            print(f"{func.__name__} took {elapsed:.4f}s")
    return wrapper

@timed
def slow_sum(n):
    return sum(range(n))

slow_sum(1_000_000)
```

A registry decorator that records functions without wrapping them:

```python
COMMANDS = {}

def command(func):
    COMMANDS[func.__name__] = func
    return func

@command
def start():
    return "starting"

print(COMMANDS["start"]())    # starting
```

## Backend Industry Example

A retry decorator with configurable attempts, delay, and exception types, plus a simple authorization check. Both are the kind of cross-cutting behaviour that should not be repeated in every function.

```python
import functools
import logging
import time

logger = logging.getLogger(__name__)


def retry(
    attempts: int = 3,
    delay: float = 0.5,
    exceptions: tuple[type[Exception], ...] = (Exception,),
):
    """Retry the decorated function when one of the given exceptions is raised.

    The wait between attempts doubles each time (exponential backoff).
    """
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, attempts + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as exc:
                    if attempt == attempts:
                        raise
                    wait = delay * 2 ** (attempt - 1)
                    logger.warning(
                        "%s failed (attempt %d of %d): %s. Retrying in %.1fs",
                        func.__name__, attempt, attempts, exc, wait,
                    )
                    time.sleep(wait)
        return wrapper
    return decorator


calls = {"count": 0}


@retry(attempts=3, delay=0.01, exceptions=(ConnectionError,))
def fetch_exchange_rate() -> float:
    """Simulate a service that fails twice before working."""
    calls["count"] += 1
    if calls["count"] < 3:
        raise ConnectionError("upstream unavailable")
    return 1.08


print(fetch_exchange_rate())    # 1.08, after two retried failures
print(calls["count"])           # 3


def require_role(role: str):
    """Allow the call only if the user dictionary contains the given role."""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(user: dict, *args, **kwargs):
            if role not in user.get("roles", ()):
                raise PermissionError(f"{func.__name__} requires role {role!r}")
            return func(user, *args, **kwargs)
        return wrapper
    return decorator


@require_role("admin")
def delete_account(user: dict, account_id: int) -> str:
    return f"account {account_id} deleted by {user['name']}"


print(delete_account({"name": "Amina", "roles": ["admin"]}, 42))
# account 42 deleted by Amina
```

Only exceptions listed in `exceptions` are retried, so a bug such as a `ValueError` fails immediately instead of being retried pointlessly. The final failure is re-raised with a bare `raise`, which preserves the original traceback. Retrying is only safe for operations that are idempotent, meaning that repeating them does not cause harm, such as reading data or setting a value.

## Common Mistakes

- Forgetting `functools.wraps`, which hides the original function's name and docstring.
- Forgetting to return the result from the wrapper, so the decorated function always returns `None`.
- Writing `@decorator` when the decorator takes arguments and needs `@decorator()`.
- Wrapping functions that are not safe to repeat in a retry decorator.
- Not accepting `*args, **kwargs` and breaking on functions with other signatures.
- Hiding important behaviour inside decorators until nobody can tell what a function actually does.

## Summary

A decorator wraps a function to add behaviour. The `@name` line is shorthand for `func = name(func)`. Use `*args, **kwargs` to pass everything through, `functools.wraps` to keep the original identity, and an extra outer function to accept decorator arguments. Stacked decorators are applied bottom-up and run outermost-first.
