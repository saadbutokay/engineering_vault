# 3.4 First-Class Functions

## Overview

In Python, a function is an object like any other. It can be assigned to a variable, stored in a list or dictionary, passed to another function, and returned from a function. Languages with this property are said to have first-class functions. It is the foundation of callbacks, decorators, sorting keys, and dispatch tables.

## Functions as Objects

```python
def greet(name):
    return f"Hello, {name}"

say_hello = greet              # no parentheses: this refers to the function
print(say_hello("Amina"))      # Hello, Amina
print(greet.__name__)          # greet
print(type(greet))             # <class 'function'>
print(callable(greet))         # True
```

Writing `greet` refers to the function object. Writing `greet("Amina")` calls it. Forgetting the difference is a common source of bugs.

Functions can be stored in data structures:

```python
operations = [str.upper, str.lower, str.title]
for operation in operations:
    print(operation("hello world"))
```

## Passing Functions to Functions

A function that accepts another function is often called a higher-order function.

```python
def apply_twice(func, value):
    return func(func(value))

def add_three(n):
    return n + 3

print(apply_twice(add_three, 10))    # 16
print(apply_twice(str.strip, "  x  "))
```

## Returning Functions

```python
def choose_formatter(style):
    if style == "upper":
        return str.upper
    return str.lower

formatter = choose_formatter("upper")
print(formatter("hello"))            # HELLO
```

## lambda

A `lambda` is a small anonymous function limited to a single expression. The value of the expression is returned automatically.

```python
square = lambda x: x * x
add = lambda a, b=1: a + b

print(square(5))        # 25
print(add(2))           # 3
```

Where lambdas shine is as short throwaway functions passed to other functions:

```python
words = ["banana", "kiwi", "apple"]
print(sorted(words, key=lambda w: len(w)))     # ['kiwi', 'apple', 'banana']
```

Guidelines:

- A lambda cannot contain statements such as `if` blocks, loops, or assignments, only one expression.
- If you assign a lambda to a name (`square = lambda x: ...`), use `def` instead. A `def` function has a proper name in tracebacks and can have a docstring.
- If the lambda becomes hard to read, write a named function.

## map and filter

Both return lazy iterators, so wrap them in `list()` to see the values.

```python
numbers = [1, 2, 3, 4, 5, 6]

doubled = list(map(lambda n: n * 2, numbers))        # [2, 4, 6, 8, 10, 12]
evens = list(filter(lambda n: n % 2 == 0, numbers))  # [2, 4, 6]

names = list(map(str.title, ["amina", "bilal"]))     # ['Amina', 'Bilal']
truthy = list(filter(None, [0, "a", "", None, 5]))   # ['a', 5]
```

Most Python developers prefer comprehensions for the same job:

```python
doubled = [n * 2 for n in numbers]
evens = [n for n in numbers if n % 2 == 0]
```

`map` and `filter` are still useful when you already have a named function, as in `map(str.title, names)`.

## The key= Parameter

`sorted`, `min`, `max`, and `list.sort` accept a function that computes what to compare.

```python
people = [("Amina", 31), ("Bilal", 25), ("Chen", 40)]

print(sorted(people, key=lambda p: p[1]))     # sorted by age
print(max(people, key=lambda p: p[1]))        # ('Chen', 40)
print(min(people, key=lambda p: p[1]))        # ('Bilal', 25)
print(sorted(["b", "A", "c"], key=str.lower)) # ['A', 'b', 'c']
```

## Basic Examples

```python
def apply_discount(price):
    return price * 0.9

def apply_tax(price):
    return price * 1.075

steps = [apply_discount, apply_tax]
price = 100
for step in steps:
    price = step(price)
print(round(price, 2))      # 96.75

calculator = {
    "add": lambda a, b: a + b,
    "multiply": lambda a, b: a * b,
}
print(calculator["add"](2, 3))        # 5
print(calculator["multiply"](2, 3))   # 6
```

## Backend Industry Example

Two patterns used constantly in services: a dispatch table that maps names to handlers, and a list of validation functions applied to input.

```python
# 1. Dispatch table: replaces a long if/elif chain
def handle_order_created(payload: dict) -> str:
    return f"created order {payload['order_id']}"


def handle_order_cancelled(payload: dict) -> str:
    return f"cancelled order {payload['order_id']}"


EVENT_HANDLERS = {
    "order.created": handle_order_created,
    "order.cancelled": handle_order_cancelled,
}


def dispatch(event_type: str, payload: dict) -> str:
    """Route an event to its handler."""
    handler = EVENT_HANDLERS.get(event_type)
    if handler is None:
        raise ValueError(f"no handler registered for {event_type!r}")
    return handler(payload)


print(dispatch("order.created", {"order_id": "A-1001"}))    # created order A-1001


# 2. Validation as a list of named checks
def not_blank(value: str) -> bool:
    return value.strip() != ""


def short_enough(value: str) -> bool:
    return len(value) <= 50


def has_no_control_characters(value: str) -> bool:
    return value.isprintable()


CHECKS = [
    ("must not be blank", not_blank),
    ("must be at most 50 characters", short_enough),
    ("must not contain control characters", has_no_control_characters),
]


def validate(value: str) -> list[str]:
    """Return a list of problems found, empty if the value is valid."""
    return [message for message, check in CHECKS if not check(value)]


print(validate("Amina"))                 # []
print(validate("   "))                   # ['must not be blank']
print(validate("x" * 60 + "\n"))
# ['must be at most 50 characters', 'must not contain control characters']
```

A new event type or a new validation rule is added by writing one function and one table entry. Neither `dispatch` nor `validate` changes. This also makes each handler and each rule easy to test on its own.

## Common Mistakes

- Writing `func()` instead of `func` when you want to pass the function itself, which passes its result instead.
- Writing complex lambdas that nobody can read.
- Assigning lambdas to names instead of defining functions with `def`.
- Forgetting that `map` and `filter` return iterators that can be consumed only once.
- Not handling a missing key in a dispatch table.

## Summary

Functions are ordinary objects. Assign them, store them in collections, pass them into other functions, and return them. Use `lambda` for short throwaway functions, `key=` to customize sorting and selection, and dispatch tables to replace chains of conditions. Prefer comprehensions over `map` and `filter` when writing new code.
