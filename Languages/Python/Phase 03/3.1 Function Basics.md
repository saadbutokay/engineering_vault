# 3.1 Function Basics

## Overview

A function is a named, reusable block of code. It takes input, does some work, and gives a result back. Functions let you avoid repeating code, give a name to an idea, and test small pieces of a program in isolation. Every backend codebase is built from thousands of small functions.

## Defining and Calling

```python
def greet(name):
    print(f"Hello, {name}!")

greet("Amina")      # Hello, Amina!
greet("Bilal")      # Hello, Bilal!
```

The pieces:

- `def` starts a function definition.
- `greet` is the function name. Use `snake_case` and a verb that says what it does.
- `name` is a parameter: a variable that receives a value when the function is called.
- The indented block is the body.
- `"Amina"` is an argument: the actual value passed in at the call.

Defining a function does not run it. The body runs only when the function is called.

## Return Values

`return` sends a value back to the caller and ends the function immediately.

```python
def add(a, b):
    return a + b

total = add(2, 3)
print(total)        # 5
```

Printing and returning are different. `print` shows something on screen and the caller gets nothing back. `return` hands a value to the calling code so it can be stored, tested, or passed on.

```python
def add_and_print(a, b):
    print(a + b)

result = add_and_print(2, 3)   # prints 5
print(result)                  # None
```

Prefer returning values from functions and printing only at the edges of the program.

## Returning Multiple Values

A function can return several values separated by commas. Python packs them into a tuple, which the caller can unpack.

```python
def min_max(values):
    return min(values), max(values)

low, high = min_max([4, 9, 1, 7])
print(low, high)        # 1 9
print(min_max([4, 9]))  # (4, 9)
```

## None as the Implicit Return

If a function reaches the end of its body without a `return` statement, or uses a bare `return`, it returns `None`.

```python
def log_message(text):
    print(text)

print(log_message("hi"))    # prints hi, then None
```

A frequent bug is using the result of a function that returns `None`, for example `items = items.sort()`, which makes `items` equal to `None`.

## Early Returns

Return as soon as the answer is known. This keeps the main logic free of deep nesting.

```python
def describe_age(age):
    if age < 0:
        return "invalid"
    if age < 18:
        return "minor"
    return "adult"
```

## Docstrings

A string placed first in the body documents the function. Editors show it as a tooltip, and `help()` prints it.

```python
def area_of_circle(radius):
    """Return the area of a circle with the given radius."""
    return 3.14159 * radius ** 2

print(area_of_circle.__doc__)
help(area_of_circle)
```

Write a one-line summary in the imperative mood. For anything with edge cases or errors, add Args, Returns, and Raises sections.

## Type Hints (Preview)

Parameters and return values can be annotated. Python does not enforce these at runtime, but editors and checkers such as mypy use them.

```python
def add(a: int, b: int) -> int:
    return a + b

def find_user(user_id: int) -> str | None:
    ...
```

The `...` placeholder (an ellipsis) means "body not written yet".

## Designing Good Functions

- Do one thing, and name it for that thing.
- Keep them short enough to read without scrolling.
- Prefer returning a value over modifying a global or printing.
- A function that always gives the same output for the same input and has no side effects is called pure. Pure functions are the easiest to test and reason about.
- A side effect is anything beyond returning a value: writing a file, changing a list that was passed in, printing, calling a network service. Keep side effects at the edges.

## Basic Examples

```python
def is_even(number):
    """Return True if the number is even."""
    return number % 2 == 0

def average(numbers):
    """Return the average of a non-empty list of numbers."""
    return sum(numbers) / len(numbers)

def full_name(first, last):
    """Return the first and last name joined with a space."""
    return f"{first} {last}".title()

print(is_even(10))              # True
print(average([80, 90, 100]))   # 90.0
print(full_name("amina", "rahman"))  # Amina Rahman
```

## Backend Industry Example

An order summary function that validates its input, returns three related values together, and uses `Decimal` for money. It has no side effects, so it is trivial to unit test.

```python
from decimal import ROUND_HALF_UP, Decimal

CENTS = Decimal("0.01")


def summarize_order(
    line_totals: list[Decimal], tax_rate: Decimal
) -> tuple[Decimal, Decimal, Decimal]:
    """Calculate the subtotal, tax, and grand total of an order.

    Args:
        line_totals: The price of each line item, already multiplied by quantity.
        tax_rate: The tax as a fraction, for example Decimal("0.075").

    Returns:
        A tuple of (subtotal, tax, total), each rounded to two decimal places.

    Raises:
        ValueError: If the order has no lines or the tax rate is negative.
    """
    if not line_totals:
        raise ValueError("an order must contain at least one line")
    if tax_rate < 0:
        raise ValueError("tax_rate must not be negative")

    subtotal = sum(line_totals, Decimal("0")).quantize(CENTS, ROUND_HALF_UP)
    tax = (subtotal * tax_rate).quantize(CENTS, ROUND_HALF_UP)
    return subtotal, tax, subtotal + tax


subtotal, tax, total = summarize_order(
    [Decimal("19.99"), Decimal("40.00")], Decimal("0.075")
)
print(subtotal, tax, total)    # 59.99 4.50 64.49
```

Validation happens first and uses early `raise` statements, so the calculation below it can assume valid input. Returning a tuple lets the caller unpack all three values at once, and because nothing is printed or stored globally, a test only needs to compare the returned values.

## Common Mistakes

- Using `print` where `return` is needed.
- Forgetting parentheses when calling: `greet` is the function object, `greet()` calls it.
- Using the result of a function that returns `None`.
- Writing functions that do many unrelated things.
- Modifying global variables from inside a function instead of returning a value.
- Forgetting that code after a `return` never runs.

## Summary

Define functions with `def`, give them clear names, take parameters, and send results back with `return`. A function with no `return` gives back `None`. Return several values as a tuple, return early to avoid nesting, write a docstring, and keep functions small, focused, and free of side effects wherever possible.
