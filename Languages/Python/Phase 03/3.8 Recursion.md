# 3.8 Recursion

## Overview

Recursion is when a function calls itself to solve a smaller version of the same problem. It is the natural way to process data that is itself nested: directory trees, JSON documents, menus, and organization charts. Every recursive function needs a clear stopping point and must move toward it with each call.

## Base Case and Recursive Case

- The base case is the simplest input, which the function answers directly without calling itself.
- The recursive case reduces the problem and calls the function again with the smaller input.

```python
def factorial(n):
    if n <= 1:                    # base case
        return 1
    return n * factorial(n - 1)   # recursive case

print(factorial(5))    # 120
```

How it unfolds:

```text
factorial(5)
5 * factorial(4)
5 * (4 * factorial(3))
5 * (4 * (3 * factorial(2)))
5 * (4 * (3 * (2 * factorial(1))))
5 * (4 * (3 * (2 * 1)))
120
```

Without a base case, or with a recursive case that does not shrink the problem, the calls never stop.

## The Call Stack and the Recursion Limit

Each call waits on the stack for the call it made to finish. Python limits the stack depth to protect against runaway recursion.

```python
import sys

print(sys.getrecursionlimit())    # 1000 by default

def forever(n):
    return forever(n + 1)

forever(0)    # RecursionError: maximum recursion depth exceeded
```

Notes:

- `sys.setrecursionlimit(n)` raises the limit, but a very high value can crash the interpreter with a real stack overflow. It is rarely the right fix.
- Python does not optimize tail calls, so a function that ends with a recursive call still uses a stack frame for each level.
- A `RecursionError` means either the base case is missing or the data is deeper than the limit allows.

## Memoization

Some recursive functions recompute the same subproblems many times. The naive Fibonacci function is the standard example.

```python
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```

`fib(35)` makes tens of millions of calls, because `fib(30)` is recomputed over and over. Memoization stores results the first time they are computed.

```python
from functools import cache

@cache
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(80))    # 23416728348467685, instantly
```

The same can be done by hand with a dictionary:

```python
def fib(n, memo=None):
    if memo is None:
        memo = {}
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
    return memo[n]
```

## Recursion on Nested Data

Recursion is at its best when the structure repeats inside itself.

```python
def flatten(nested):
    """Return all items of an arbitrarily nested list as a flat list."""
    result = []
    for item in nested:
        if isinstance(item, list):
            result.extend(flatten(item))     # recursive case
        else:
            result.append(item)              # base case: not a list
    return result

print(flatten([1, [2, [3, 4]], 5, [[6]]]))   # [1, 2, 3, 4, 5, 6]
```

## When to Use Iteration Instead

Prefer a loop when:

- The depth could be large, such as walking a list of 100,000 items. Recursion will hit the limit.
- The problem is naturally a loop, such as summing numbers or counting up.
- Performance matters and each call adds overhead.

Prefer recursion when the data is a tree or the problem splits into smaller copies of itself and the depth is modest.

Any recursion can be rewritten with an explicit stack. This avoids the recursion limit and is the standard approach for very deep data.

```python
def flatten_iterative(nested):
    stack = [nested]
    result = []
    while stack:
        current = stack.pop()
        if isinstance(current, list):
            stack.extend(reversed(current))   # reversed keeps the original order
        else:
            result.append(current)
    return result

print(flatten_iterative([1, [2, [3, 4]], 5, [[6]]]))   # [1, 2, 3, 4, 5, 6]
```

## Basic Examples

```python
def countdown(n):
    if n == 0:
        print("liftoff")
        return
    print(n)
    countdown(n - 1)

countdown(3)    # 3, 2, 1, liftoff

def sum_list(numbers):
    if not numbers:                       # base case: empty list
        return 0
    return numbers[0] + sum_list(numbers[1:])

print(sum_list([1, 2, 3, 4]))             # 10

def power(base, exponent):
    if exponent == 0:
        return 1
    return base * power(base, exponent - 1)

print(power(2, 10))                       # 1024
```

`sum_list` is a teaching example. In real code use `sum()`, which is faster and has no depth limit.

## Backend Industry Example

JSON data arriving from clients and APIs is nested to unknown depth. Before logging a request body, any sensitive values must be removed wherever they appear. A recursive function handles this cleanly.

```python
SENSITIVE_KEYS = {"password", "token", "secret", "authorization", "card_number"}


def redact(value: object) -> object:
    """Return a copy of nested JSON-like data with sensitive values hidden."""
    if isinstance(value, dict):
        return {
            key: "[REDACTED]" if str(key).lower() in SENSITIVE_KEYS else redact(item)
            for key, item in value.items()
        }
    if isinstance(value, list):
        return [redact(item) for item in value]
    return value                              # base case: a plain value


request_body = {
    "user": {"name": "Amina", "password": "hunter2"},
    "headers": {"Authorization": "Bearer abc123", "Accept": "application/json"},
    "items": [
        {"sku": "A1", "meta": {"token": "xyz"}},
        {"sku": "B2", "meta": {}},
    ],
}

print(redact(request_body))
# {'user': {'name': 'Amina', 'password': '[REDACTED]'},
#  'headers': {'Authorization': '[REDACTED]', 'Accept': 'application/json'},
#  'items': [{'sku': 'A1', 'meta': {'token': '[REDACTED]'}}, {'sku': 'B2', 'meta': {}}]}
print(request_body["user"]["password"])       # hunter2: the original is unchanged
```

The function never modifies its input. It builds new dictionaries and lists, so the original request is untouched and can still be processed.

Data from outside a system should never be trusted to be shallow. A client can send deliberately deep nesting, which would cause a `RecursionError` in a recursive function. Where the input is untrusted, limit the depth explicitly:

```python
MAX_DEPTH = 50


def redact_safe(value: object, depth: int = 0) -> object:
    """Same as redact, but refuse data nested deeper than MAX_DEPTH."""
    if depth > MAX_DEPTH:
        raise ValueError("payload is nested too deeply")
    if isinstance(value, dict):
        return {
            key: "[REDACTED]" if str(key).lower() in SENSITIVE_KEYS
            else redact_safe(item, depth + 1)
            for key, item in value.items()
        }
    if isinstance(value, list):
        return [redact_safe(item, depth + 1) for item in value]
    return value


print(redact_safe({"a": {"password": "x"}}))    # {'a': {'password': '[REDACTED]'}}
```

## Common Mistakes

- Forgetting the base case, or writing one that is never reached.
- Not shrinking the problem in the recursive case, causing infinite recursion.
- Using recursion for simple repetition that a loop handles better.
- Recomputing the same subproblems without memoization.
- Recursing over very deep or untrusted data without a depth limit.
- Raising the recursion limit instead of fixing the algorithm.

## Summary

A recursive function has a base case that stops it and a recursive case that moves toward the base case. Recursion fits nested and tree-shaped data. Python limits stack depth, so use memoization to avoid repeated work and use loops or an explicit stack for deep or flat problems. When processing untrusted nested input, enforce a maximum depth.
