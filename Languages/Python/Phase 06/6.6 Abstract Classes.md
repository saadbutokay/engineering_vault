# 6.6 Abstract Classes

## Overview

An abstract class defines a set of methods that every subclass must provide, without implementing them itself. It acts as an interface or contract: "anything that wants to be a payment gateway must have `charge` and `refund`." Python supports this through the `abc` module (abstract base classes).

## Defining an Abstract Class

```python
from abc import ABC, abstractmethod


class Shape(ABC):
    @abstractmethod
    def area(self):
        """Return the area of the shape."""

    @abstractmethod
    def perimeter(self):
        """Return the perimeter of the shape."""
```

- Inherit from `ABC`.
- Mark each required method with `@abstractmethod`. Its body is usually only a docstring.

An abstract class cannot be instantiated:

```python
shape = Shape()
# TypeError: Can't instantiate abstract class Shape without an implementation
#            for abstract methods 'area', 'perimeter'
```

## Implementing the Contract

A subclass must override every abstract method. Until it does, it is abstract too and cannot be instantiated.

```python
class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

    def perimeter(self):
        return 2 * (self.width + self.height)


class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14159 * self.radius ** 2
    # perimeter is missing


Rectangle(3, 4)       # works
Circle(2)             # TypeError: Can't instantiate abstract class Circle ... 'perimeter'
```

The error appears when the object is created, not later when the missing method is called. This catches incomplete implementations immediately.

## Concrete Methods in Abstract Classes

An abstract class can also contain ordinary methods that rely on the abstract ones. This is the template method pattern: the base class fixes the algorithm and subclasses fill in the steps.

```python
class Shape(ABC):
    @abstractmethod
    def area(self):
        ...

    def describe(self):                       # concrete, uses the abstract method
        return f"{type(self).__name__} with area {self.area():.2f}"
```

Every subclass gets `describe` for free.

## Abstract Properties and Class Methods

```python
class Report(ABC):
    @property
    @abstractmethod
    def title(self):
        ...

    @classmethod
    @abstractmethod
    def from_rows(cls, rows):
        ...
```

Put `@abstractmethod` as the innermost decorator, directly above `def`.

## Why Use Abstract Classes

- They document the required interface in one place.
- They fail early, at instantiation, when an implementation is incomplete.
- They let code depend on the abstraction and not on a concrete class. A function that accepts a `Shape` works with every shape.
- They give shared helper methods to all implementations.

Python is also happy with duck typing: if an object has the right methods, you can use it, with no inheritance needed. Abstract classes are most valuable when you want an explicit, enforced contract, typically at the boundary between parts of a system or for plugin-style extension points. Python also supports structural interfaces through `typing.Protocol`, which checks the shape of an object without requiring inheritance.

## Virtual Subclasses

`ABC.register` declares an existing class to be a subclass without inheriting from it. `isinstance` and `issubclass` then return `True`. This is rarely needed in application code.

## Basic Examples

```python
from abc import ABC, abstractmethod


class Animal(ABC):
    def __init__(self, name):
        self.name = name

    @abstractmethod
    def speak(self):
        ...

    def introduce(self):
        return f"{self.name} says {self.speak()}"


class Dog(Animal):
    def speak(self):
        return "woof"


class Cat(Animal):
    def speak(self):
        return "meow"


for pet in (Dog("Rex"), Cat("Tom")):
    print(pet.introduce())       # Rex says woof, Tom says meow

print(isinstance(Dog("x"), Animal))    # True
```

## Backend Industry Example

A storage abstraction. Application code depends on `BlobStorage` and does not know whether files live in memory (tests), on local disk (development), or in a cloud bucket (production). The abstract class defines the contract and provides text helpers that work on top of it.

```python
import tempfile
from abc import ABC, abstractmethod
from pathlib import Path


class BlobStorage(ABC):
    """Contract for storing and retrieving binary objects by key."""

    @abstractmethod
    def put(self, key: str, data: bytes) -> None:
        """Store data under key, replacing anything already there."""

    @abstractmethod
    def get(self, key: str) -> bytes:
        """Return the data stored under key or raise KeyError."""

    @abstractmethod
    def exists(self, key: str) -> bool:
        """Return True if key is stored."""

    # Concrete helpers built on the abstract operations
    def put_text(self, key: str, text: str) -> None:
        self.put(key, text.encode("utf-8"))

    def get_text(self, key: str) -> str:
        return self.get(key).decode("utf-8")


class MemoryStorage(BlobStorage):
    """Keeps everything in a dictionary. Ideal for tests."""

    def __init__(self) -> None:
        self._data: dict[str, bytes] = {}

    def put(self, key: str, data: bytes) -> None:
        self._data[key] = data

    def get(self, key: str) -> bytes:
        try:
            return self._data[key]
        except KeyError:
            raise KeyError(f"no object stored under {key!r}") from None

    def exists(self, key: str) -> bool:
        return key in self._data


class LocalDiskStorage(BlobStorage):
    """Stores each object as a file below a root directory."""

    def __init__(self, root: Path) -> None:
        self._root = root.resolve()
        self._root.mkdir(parents=True, exist_ok=True)

    def _path_for(self, key: str) -> Path:
        path = (self._root / key).resolve()
        if not path.is_relative_to(self._root):
            raise ValueError(f"invalid key: {key!r}")
        return path

    def put(self, key: str, data: bytes) -> None:
        path = self._path_for(key)
        path.parent.mkdir(parents=True, exist_ok=True)
        path.write_bytes(data)

    def get(self, key: str) -> bytes:
        path = self._path_for(key)
        if not path.is_file():
            raise KeyError(f"no object stored under {key!r}")
        return path.read_bytes()

    def exists(self, key: str) -> bool:
        return self._path_for(key).is_file()


def archive_report(storage: BlobStorage, report_id: str, content: str) -> None:
    """Application code: depends only on the BlobStorage contract."""
    storage.put_text(f"reports/{report_id}.txt", content)


class IncompleteStorage(BlobStorage):
    def put(self, key: str, data: bytes) -> None:
        pass


try:
    IncompleteStorage()
except TypeError as exc:
    print("rejected:", exc)

with tempfile.TemporaryDirectory() as workdir:
    for storage in (MemoryStorage(), LocalDiskStorage(Path(workdir))):
        archive_report(storage, "2026-03", "total revenue: 120000")
        print(type(storage).__name__, storage.get_text("reports/2026-03.txt"))
```

`archive_report` runs unchanged against both implementations. Adding a cloud implementation means writing a class with the same three methods. The abstract base class guarantees that none of them is forgotten, because `IncompleteStorage()` fails at once with a clear message.

## Common Mistakes

- Forgetting to inherit from `ABC`, in which case `@abstractmethod` has no effect and incomplete subclasses can be instantiated.
- Putting `@abstractmethod` above `@property` instead of below it.
- Creating abstract classes for a single implementation, when a concrete class would do.
- Defining huge interfaces with many methods that implementations do not need. Keep contracts small.
- Raising `NotImplementedError` in a regular method and expecting the early failure that `@abstractmethod` provides.
- Instantiating an abstract class directly for testing instead of using a small concrete subclass.

## Summary

Abstract classes, built with `ABC` and `@abstractmethod`, define a contract that subclasses must fulfil, and Python refuses to create instances of incomplete subclasses. They can also hold concrete helper methods that build on the abstract ones. Use them for stable extension points and boundaries, keep interfaces small, and let application code depend on the abstraction so that implementations can be swapped for tests, development, and production.
