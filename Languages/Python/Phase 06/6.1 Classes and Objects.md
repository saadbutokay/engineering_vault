# 6.1 Classes and Objects

## Overview

A class is a blueprint that describes what data something holds and what it can do. An object, also called an instance, is one concrete thing built from that blueprint. Classes let you bundle data and the functions that work on it into a single unit, which is how most large programs are organized.

## Defining a Class

```python
class Dog:
    species = "Canis familiaris"          # class attribute, shared by all dogs

    def __init__(self, name, age):
        self.name = name                  # instance attribute, one per dog
        self.age = age

    def bark(self):
        return f"{self.name} says woof"

    def birthday(self):
        self.age += 1


rex = Dog("Rex", 3)
bella = Dog("Bella", 5)

print(rex.name)         # Rex
print(rex.bark())       # Rex says woof
rex.birthday()
print(rex.age)          # 4
print(bella.age)        # 5, a separate object with its own data
```

Parts:

- `class Dog:` defines the class. Class names use `PascalCase`.
- `Dog("Rex", 3)` creates an instance. Python creates an empty object and then calls `__init__` on it with the arguments you passed.
- `__init__` is the initializer. It sets up the new object's starting state. It must not return a value.
- `self` is the instance the method is working on. Python passes it automatically as the first argument when you call `rex.bark()`. The name `self` is a strong convention, not a keyword.
- A function defined inside a class is called a method.

`rex.bark()` is shorthand for `Dog.bark(rex)`.

## Instance Attributes versus Class Attributes

An instance attribute is created by assigning to `self.name` and belongs to one object. A class attribute is defined in the class body and belongs to the class, and every instance can read it.

```python
print(rex.species)       # Canis familiaris
print(Dog.species)       # the same value, read from the class
```

Attribute lookup checks the instance first, then the class. Assigning through an instance creates an instance attribute that hides the class attribute for that object only:

```python
rex.species = "wolf"     # creates an instance attribute on rex
print(rex.species)       # wolf
print(bella.species)     # Canis familiaris
print(Dog.species)       # Canis familiaris
```

### The Mutable Class Attribute Trap

A mutable class attribute is shared by every instance, which is almost never what you want.

```python
class Basket:
    items = []                       # one list shared by all baskets

    def add(self, item):
        self.items.append(item)


a = Basket()
b = Basket()
a.add("apple")
print(b.items)                       # ['apple']
```

Create per-object mutable data in `__init__`:

```python
class Basket:
    def __init__(self):
        self.items = []              # a new list for each basket
```

Use class attributes for constants and for values that really are shared, such as a default or a counter of all instances.

## Inspecting Objects

```python
print(type(rex))                    # <class '__main__.Dog'>
print(isinstance(rex, Dog))         # True
print(hasattr(rex, "name"))         # True
print(getattr(rex, "color", "unknown"))   # unknown
print(rex.__dict__)                 # {'name': 'Rex', 'age': 4, 'species': 'wolf'}
print(vars(rex))                    # the same dictionary
```

You can add attributes to an instance at any time (`rex.color = "brown"`), but declaring all attributes in `__init__` keeps objects predictable.

## Methods Calling Methods

Methods call each other through `self`:

```python
class Account:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("deposit must be positive")
        self.balance += amount

    def withdraw(self, amount):
        if amount > self.balance:
            raise ValueError("insufficient funds")
        self.balance -= amount

    def transfer_to(self, other, amount):
        self.withdraw(amount)
        other.deposit(amount)
```

## When to Use a Class

Use a class when you have data and behaviour that belong together and when several instances with their own state are useful: an account, a connection, a cache, an order. If you only need a function, write a function. If you only need a bundle of values, a dataclass or a dictionary is often better.

## Basic Examples

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

    def scale(self, factor):
        self.width *= factor
        self.height *= factor


r = Rectangle(3, 4)
print(r.area())      # 12
r.scale(2)
print(r.area())      # 48


class Counter:
    total_created = 0                # class attribute counting all instances

    def __init__(self):
        Counter.total_created += 1


Counter()
Counter()
print(Counter.total_created)         # 2
```

## Backend Industry Example

An in-memory cache whose entries expire after a fixed time. The class owns its state, validates its configuration, hides its storage behind methods, and takes the clock as a parameter so that tests can control time.

```python
import time
from collections.abc import Callable


class TTLCache:
    """In-memory cache whose entries expire after a fixed number of seconds."""

    def __init__(
        self, ttl_seconds: float, clock: Callable[[], float] = time.monotonic
    ) -> None:
        if ttl_seconds <= 0:
            raise ValueError("ttl_seconds must be positive")
        self.ttl_seconds = ttl_seconds
        self._clock = clock
        self._entries: dict[str, tuple[float, object]] = {}

    def set(self, key: str, value: object) -> None:
        """Store a value that expires ttl_seconds from now."""
        self._entries[key] = (self._clock() + self.ttl_seconds, value)

    def get(self, key: str, default: object = None) -> object:
        """Return the value for key, or default if missing or expired."""
        entry = self._entries.get(key)
        if entry is None:
            return default
        expires_at, value = entry
        if self._clock() >= expires_at:
            del self._entries[key]
            return default
        return value

    def purge_expired(self) -> int:
        """Remove all expired entries and return how many were removed."""
        now = self._clock()
        expired = [
            key for key, (expires_at, _) in self._entries.items() if expires_at <= now
        ]
        for key in expired:
            del self._entries[key]
        return len(expired)

    def size(self) -> int:
        return len(self._entries)


# A fake clock makes the behaviour testable without sleeping
current_time = [0.0]
cache = TTLCache(ttl_seconds=60, clock=lambda: current_time[0])

cache.set("user:1", {"name": "Amina"})
print(cache.get("user:1"))            # {'name': 'Amina'}

current_time[0] = 61.0                # one minute later
print(cache.get("user:1", "expired")) # expired
print(cache.size())                   # 0
```

Each `TTLCache` instance has its own dictionary, so one cache can hold user data with a one-minute lifetime while another holds configuration with a one-hour lifetime. The leading underscore on `_clock` and `_entries` marks them as internal details that callers should not touch. Passing the clock in is a simple form of dependency injection that makes time-based code testable.

## Common Mistakes

- Forgetting `self` as the first parameter of a method (`TypeError: takes 0 positional arguments but 1 was given`).
- Forgetting `self.` when assigning, which creates a local variable instead of an attribute.
- Using a mutable class attribute for per-instance data.
- Doing heavy work such as network calls inside `__init__`.
- Returning a value from `__init__`.
- Creating classes for things that a simple function would handle.
- Letting objects have different sets of attributes depending on what happened, instead of setting everything in `__init__`.

## Summary

A class defines the data and behaviour of a kind of object, and each instance holds its own state in instance attributes. `__init__` sets up that state, `self` refers to the current instance, and class attributes hold values shared by all instances. Keep per-instance mutable data in `__init__`, hide internals with a leading underscore, and inject dependencies such as clocks so that classes are easy to test.
