# 6.3 Dunder Methods

## Overview

Dunder methods ("double underscore" methods, such as `__init__` and `__repr__`) are special methods that Python calls for you in response to syntax and built-in functions. When you write `len(obj)`, `a + b`, `a == b`, `for x in obj`, or `print(obj)`, Python looks for a matching dunder method on the object. Implementing them makes your own classes behave like built-in types.

You do not call dunder methods directly. You define them and Python calls them.

## `__repr__` and `__str__`

- `__repr__` returns an unambiguous description meant for developers. It is used in the REPL, in logs, in debuggers, and inside containers such as lists. Ideally it looks like code that could recreate the object.
- `__str__` returns a readable description meant for end users. It is used by `print()` and `str()`. If `__str__` is missing, Python falls back to `__repr__`.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Point({self.x!r}, {self.y!r})"

    def __str__(self):
        return f"({self.x}, {self.y})"


p = Point(3, 4)
print(p)           # (3, 4)
print(repr(p))     # Point(3, 4)
print([p])         # [Point(3, 4)], containers use repr
```

Always write `__repr__`. Without it, you see `<__main__.Point object at 0x7f...>`, which is useless in logs.

## Equality and Hashing

`__eq__` defines `==`. By default, two objects are equal only if they are the same object.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return (self.x, self.y) == (other.x, other.y)

    def __hash__(self):
        return hash((self.x, self.y))


print(Point(1, 2) == Point(1, 2))     # True
print(Point(1, 2) == (1, 2))          # False
print(len({Point(1, 2), Point(1, 2)}))   # 1, usable in sets and as dictionary keys
```

Rules:

- Returning `NotImplemented` (not raising an error) for unsupported types lets Python try the other operand and then fall back to a sensible default.
- Objects that are equal must have equal hashes. When you define `__eq__` without `__hash__`, Python sets `__hash__` to `None`, making the class unhashable. Define both, or neither.
- Only make an object hashable if it is immutable in the fields used for the hash. Changing a key's hash while it is inside a set or dictionary breaks lookups.

## Ordering

`__lt__`, `__le__`, `__gt__`, and `__ge__` define `<`, `<=`, `>`, and `>=`. You can define one, plus `__eq__`, and let `functools.total_ordering` generate the rest. Defining `__lt__` is enough for `sorted`, `min`, and `max`.

```python
from functools import total_ordering


@total_ordering
class Version:
    def __init__(self, major, minor):
        self.major = major
        self.minor = minor

    def __eq__(self, other):
        if not isinstance(other, Version):
            return NotImplemented
        return (self.major, self.minor) == (other.major, other.minor)

    def __lt__(self, other):
        if not isinstance(other, Version):
            return NotImplemented
        return (self.major, self.minor) < (other.major, other.minor)

    def __repr__(self):
        return f"Version({self.major}, {self.minor})"


print(sorted([Version(1, 10), Version(1, 2), Version(0, 9)]))
# [Version(0, 9), Version(1, 2), Version(1, 10)]
print(Version(2, 0) >= Version(1, 9))     # True
```

## Container Behaviour

| Method | Used by |
| --- | --- |
| `__len__` | `len(obj)`, and truthiness when `__bool__` is missing |
| `__getitem__` | `obj[key]`, and iteration if `__iter__` is missing |
| `__setitem__` | `obj[key] = value` |
| `__delitem__` | `del obj[key]` |
| `__iter__` | `for x in obj`, `list(obj)` |
| `__contains__` | `x in obj` |

```python
class Playlist:
    def __init__(self, songs=None):
        self._songs = list(songs or [])

    def add(self, song):
        self._songs.append(song)

    def __len__(self):
        return len(self._songs)

    def __getitem__(self, index):
        return self._songs[index]

    def __iter__(self):
        return iter(self._songs)

    def __contains__(self, song):
        return song in self._songs


playlist = Playlist(["Intro", "Verse", "Outro"])
print(len(playlist))            # 3
print(playlist[1])              # Verse
print(playlist[-1])             # Outro
print("Verse" in playlist)      # True
for song in playlist:
    print(song)
```

## Other Useful Methods

`__call__` makes an instance callable like a function:

```python
class Multiplier:
    def __init__(self, factor):
        self.factor = factor

    def __call__(self, value):
        return value * self.factor


double = Multiplier(2)
print(double(21))        # 42
```

`__bool__` defines truthiness. If missing, Python uses `__len__`, and an object with neither is always truthy.

## Operator Overloading

Arithmetic operators map to dunder methods.

| Operator | Method | Reflected method |
| --- | --- | --- |
| `a + b` | `__add__` | `__radd__` |
| `a - b` | `__sub__` | `__rsub__` |
| `a * b` | `__mul__` | `__rmul__` |
| `a / b` | `__truediv__` | `__rtruediv__` |
| `-a` | `__neg__` | |
| `abs(a)` | `__abs__` | |

The reflected version is tried when the left operand does not know how to handle the right one. This is what makes `3 * vector` work as well as `vector * 3`, and it is why `sum()` (which starts with `0 + first_item`) works with your own types if you define `__radd__`.

```python
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(self.x + other.x, self.y + other.y)

    def __mul__(self, scalar):
        if not isinstance(scalar, (int, float)):
            return NotImplemented
        return Vector(self.x * scalar, self.y * scalar)

    __rmul__ = __mul__

    def __neg__(self):
        return Vector(-self.x, -self.y)

    def __abs__(self):
        return (self.x ** 2 + self.y ** 2) ** 0.5


v = Vector(3, 4)
print(v + Vector(1, 1))     # Vector(4, 5)
print(v * 2)                # Vector(6, 8)
print(2 * v)                # Vector(6, 8)
print(-v, abs(v))           # Vector(-3, -4) 5.0
```

Operators should return new objects and not modify their operands. Overload an operator only when its meaning is obvious. `a + b` for vectors is natural, `order + customer` is not.

## Basic Examples

```python
class Temperature:
    def __init__(self, degrees):
        self.degrees = degrees

    def __repr__(self):
        return f"Temperature({self.degrees})"

    def __lt__(self, other):
        return self.degrees < other.degrees


readings = [Temperature(21), Temperature(18), Temperature(25)]
print(min(readings))            # Temperature(18)
print(sorted(readings))         # sorted by degrees
```

## Backend Industry Example

A `Money` value object. It stores an exact `Decimal` amount with a currency, refuses to mix currencies, behaves correctly in sets, dictionaries, sorting, and `sum`, and has a readable string form. Alongside it, a small container class shows `__len__`, `__iter__`, and `__getitem__`.

```python
from decimal import ROUND_HALF_UP, Decimal
from functools import total_ordering


@total_ordering
class Money:
    """An amount of money in one currency. Instances are treated as immutable."""

    def __init__(self, amount: Decimal | str | int, currency: str) -> None:
        if isinstance(amount, float):
            raise TypeError("use str or Decimal for money, floats are inexact")
        self._amount = Decimal(amount).quantize(Decimal("0.01"), ROUND_HALF_UP)
        self._currency = currency.upper()

    @property
    def amount(self) -> Decimal:
        return self._amount

    @property
    def currency(self) -> str:
        return self._currency

    def _check_same_currency(self, other: "Money") -> None:
        if self._currency != other._currency:
            raise ValueError(f"cannot combine {self._currency} and {other._currency}")

    def __repr__(self) -> str:
        return f"Money({str(self._amount)!r}, {self._currency!r})"

    def __str__(self) -> str:
        return f"{self._amount:,.2f} {self._currency}"

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Money):
            return NotImplemented
        return (self._amount, self._currency) == (other._amount, other._currency)

    def __hash__(self) -> int:
        return hash((self._amount, self._currency))

    def __lt__(self, other: "Money") -> bool:
        if not isinstance(other, Money):
            return NotImplemented
        self._check_same_currency(other)
        return self._amount < other._amount

    def __add__(self, other: "Money") -> "Money":
        if not isinstance(other, Money):
            return NotImplemented
        self._check_same_currency(other)
        return Money(self._amount + other._amount, self._currency)

    def __sub__(self, other: "Money") -> "Money":
        if not isinstance(other, Money):
            return NotImplemented
        self._check_same_currency(other)
        return Money(self._amount - other._amount, self._currency)

    def __mul__(self, factor: int | Decimal) -> "Money":
        if isinstance(factor, bool) or not isinstance(factor, (int, Decimal)):
            return NotImplemented
        return Money(self._amount * factor, self._currency)

    __rmul__ = __mul__

    def __bool__(self) -> bool:
        return self._amount != 0


class Basket:
    """A collection of prices that behaves like a read-only sequence."""

    def __init__(self, prices: list[Money] | None = None) -> None:
        self._prices = list(prices or [])

    def add(self, price: Money) -> None:
        self._prices.append(price)

    def __len__(self) -> int:
        return len(self._prices)

    def __iter__(self):
        return iter(self._prices)

    def __getitem__(self, index: int) -> Money:
        return self._prices[index]

    def total(self, currency: str) -> Money:
        return sum(self._prices, Money(0, currency))


price = Money("19.99", "usd")
shipping = Money("5.00", "USD")

print(price + shipping)                  # 24.99 USD
print(price * 3)                         # 59.97 USD
print(3 * price)                         # 59.97 USD
print(repr(price))                       # Money('19.99', 'USD')
print(price > shipping, max(price, shipping))   # True 19.99 USD
print(Money("10", "USD") == Money("10.00", "USD"))   # True
print(len({Money("1", "USD"), Money("1.00", "USD")}))   # 1

try:
    price + Money("5.00", "EUR")
except ValueError as exc:
    print(exc)                           # cannot combine USD and EUR

basket = Basket([price, shipping, Money("2.50", "USD")])
print(len(basket), basket[0], basket.total("USD"))   # 3 19.99 USD 27.49 USD
print(sorted(basket))                    # sorted by amount
print(bool(Money(0, "USD")))             # False
```

The class rejects floats at the door, so inexact values never enter. Because `__eq__` and `__hash__` agree, `Money` works as a dictionary key or set member. Returning `NotImplemented` rather than raising lets Python give a clear `TypeError` when someone writes `price + 5`.

## Common Mistakes

- Defining `__eq__` without `__hash__` and then being unable to use the object in sets or as a dictionary key.
- Making mutable objects hashable and then changing them while they are stored in a set.
- Raising `TypeError` instead of returning `NotImplemented` for unsupported operand types.
- Writing a `__repr__` that is not useful, or one that raises exceptions.
- Overloading operators with unintuitive meanings.
- Modifying an operand inside `__add__` instead of returning a new object.
- Forgetting `__radd__` or `__rmul__` and being surprised that `sum()` or `3 * obj` fails.

## Summary

Dunder methods connect your classes to Python's syntax. Write `__repr__` for every class and `__str__` when a friendly form is needed. Define `__eq__` together with `__hash__`, use `total_ordering` for comparisons, implement `__len__`, `__iter__`, `__getitem__`, and `__contains__` for container behaviour, and overload arithmetic operators only where the meaning is natural. Return `NotImplemented` for operand types you do not handle.
