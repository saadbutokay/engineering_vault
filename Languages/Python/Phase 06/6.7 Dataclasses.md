# 6.7 Dataclasses

## Overview

Many classes exist only to hold data: a point, a user record, an order line. Writing `__init__`, `__repr__`, and `__eq__` by hand for each one is repetitive. The `@dataclass` decorator generates those methods from a list of annotated fields, so you describe the data and Python writes the boilerplate.

## The Basics

Compare a manual class:

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Point(x={self.x!r}, y={self.y!r})"

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return (self.x, self.y) == (other.x, other.y)
```

with the dataclass version:

```python
from dataclasses import dataclass


@dataclass
class Point:
    x: float
    y: float


p = Point(3, 4)
print(p)                     # Point(x=3, y=4)
print(p == Point(3, 4))      # True
print(p.x)                   # 3
```

Each annotated class variable becomes a field. The decorator generates `__init__`, `__repr__`, and `__eq__`. The type annotations document the fields but Python does not enforce them at runtime: `Point("a", "b")` is accepted.

## Defaults and field()

Fields can have default values. A field with a default must come after fields without one.

```python
@dataclass
class User:
    name: str
    active: bool = True
    role: str = "member"


print(User("Amina"))        # User(name='Amina', active=True, role='member')
```

Mutable defaults such as lists and dictionaries are rejected, because they would be shared between instances.

```python
@dataclass
class Team:
    members: list = []
# ValueError: mutable default <class 'list'> for field members is not allowed: use default_factory
```

Use `field(default_factory=...)`:

```python
from dataclasses import dataclass, field


@dataclass
class Team:
    name: str
    members: list[str] = field(default_factory=list)


a = Team("A")
b = Team("B")
a.members.append("Amina")
print(b.members)            # [], each instance has its own list
```

`field()` has more options:

| Option | Effect |
| --- | --- |
| `default=` | a default value |
| `default_factory=` | a function that builds the default |
| `repr=False` | leave the field out of `__repr__` (for secrets or long data) |
| `compare=False` | leave the field out of `==` and ordering |
| `init=False` | not a constructor parameter, set it yourself |
| `kw_only=True` | this field must be passed by keyword |

```python
@dataclass
class Credentials:
    username: str
    password: str = field(repr=False)       # never shown in logs or tracebacks
```

## Frozen Dataclasses

`frozen=True` makes instances immutable. Assigning to a field raises `FrozenInstanceError`. A frozen dataclass with `eq=True` (the default) also gets a `__hash__`, so it can be used as a dictionary key or in a set.

```python
@dataclass(frozen=True)
class Coordinate:
    lat: float
    lon: float


c = Coordinate(23.8, 90.4)
c.lat = 0                       # FrozenInstanceError: cannot assign to field 'lat'
print({c: "Dhaka"})             # works: frozen dataclasses are hashable
```

A regular (non-frozen) dataclass with `eq=True` is not hashable, so it cannot be used as a key.

## order=True

`order=True` generates `<`, `<=`, `>`, and `>=` by comparing the fields as a tuple in the order they are declared.

```python
@dataclass(order=True)
class Version:
    major: int
    minor: int


print(Version(1, 2) < Version(1, 10))        # True
print(sorted([Version(2, 0), Version(1, 5)]))
```

## slots=True and kw_only=True

Python 3.10 added two useful options.

```python
@dataclass(slots=True)
class Event:
    name: str
    timestamp: float
```

`slots=True` stores fields in a compact fixed layout instead of a per-instance dictionary, which saves memory when you create many objects and rejects misspelled attribute names.

```python
@dataclass(kw_only=True)
class Connection:
    host: str
    port: int = 5432
    timeout: float = 5.0


Connection(host="db.example.com", timeout=10)    # fields must be named
```

`kw_only=True` forces every field to be passed by keyword, which makes calls readable and removes the "fields with defaults must come last" restriction.

## `__post_init__`

`__post_init__` runs right after the generated `__init__`. Use it to validate values or to compute derived fields.

```python
@dataclass
class Rectangle:
    width: float
    height: float
    area: float = field(init=False)

    def __post_init__(self):
        if self.width <= 0 or self.height <= 0:
            raise ValueError("width and height must be positive")
        self.area = self.width * self.height


print(Rectangle(3, 4).area)        # 12
```

For a frozen dataclass, derived values should be computed in a property, or assigned with `object.__setattr__`, because normal assignment is blocked.

## Helper Functions

```python
from dataclasses import asdict, astuple, fields, replace

p = Point(3, 4)
print(asdict(p))              # {'x': 3, 'y': 4}, nested dataclasses are converted too
print(astuple(p))             # (3, 4)
print([f.name for f in fields(p)])    # ['x', 'y']

moved = replace(p, x=10)      # a copy with one field changed
print(moved)                  # Point(x=10, y=4)
```

`replace` is the normal way to "modify" a frozen dataclass: build a new instance with the changed field. It runs `__init__` and `__post_init__` again, so validation applies to the new object.

## Inheritance

Dataclasses can inherit from each other. Fields of the parent come first, which can clash with the "defaults last" rule.

```python
@dataclass
class Base:
    id: int
    active: bool = True


@dataclass
class Child(Base):
    name: str          # TypeError: non-default argument 'name' follows default argument
```

Making the dataclasses `kw_only=True` avoids the problem.

## Dataclasses and Other Options

| Tool | Best for |
| --- | --- |
| `dict` | quick, untyped, short-lived data, and JSON in transit |
| `namedtuple` | small immutable records that behave like tuples |
| `@dataclass` | structured data inside your program, with optional behaviour |
| a validation library such as pydantic | parsing and validating untrusted input such as request bodies, with real type checking and conversion |

Dataclasses do not validate or convert types. Validate at the boundaries where data enters your program.

## Basic Examples

```python
from dataclasses import dataclass, field


@dataclass
class Student:
    name: str
    grades: list[int] = field(default_factory=list)

    def average(self) -> float:
        return sum(self.grades) / len(self.grades) if self.grades else 0.0


s = Student("Amina", [90, 85, 100])
print(s)               # Student(name='Amina', grades=[90, 85, 100])
print(s.average())     # 91.66666666666667
```

## Backend Industry Example

An immutable order model. Lines validate themselves on creation, totals are computed from the data, "changes" create new orders with `replace`, and the model converts to and from the dictionaries used at the API boundary.

```python
import json
from dataclasses import asdict, dataclass, replace
from decimal import Decimal


@dataclass(frozen=True, slots=True)
class OrderLine:
    sku: str
    quantity: int
    unit_price: Decimal

    def __post_init__(self) -> None:
        if self.quantity <= 0:
            raise ValueError(f"quantity must be positive for {self.sku}")
        if self.unit_price < 0:
            raise ValueError(f"unit_price must not be negative for {self.sku}")

    @property
    def total(self) -> Decimal:
        return self.unit_price * self.quantity


@dataclass(frozen=True, kw_only=True)
class Order:
    order_id: str
    customer_email: str
    lines: tuple[OrderLine, ...] = ()
    status: str = "pending"

    @property
    def total(self) -> Decimal:
        return sum((line.total for line in self.lines), Decimal("0"))

    def with_line(self, line: OrderLine) -> "Order":
        return replace(self, lines=self.lines + (line,))

    def with_status(self, status: str) -> "Order":
        return replace(self, status=status)

    @classmethod
    def from_dict(cls, data: dict) -> "Order":
        lines = tuple(
            OrderLine(item["sku"], int(item["quantity"]), Decimal(str(item["unit_price"])))
            for item in data.get("lines", [])
        )
        return cls(
            order_id=data["order_id"],
            customer_email=data["customer_email"],
            lines=lines,
        )


order = Order.from_dict(
    {
        "order_id": "A-1001",
        "customer_email": "amina@example.com",
        "lines": [
            {"sku": "pen", "quantity": 3, "unit_price": "2.50"},
            {"sku": "notebook", "quantity": 1, "unit_price": 12.99},
        ],
    }
)
print(order.total)                         # 20.49

paid = order.with_status("paid")
print(order.status, paid.status)           # pending paid, the original is unchanged

try:
    order.status = "shipped"
except AttributeError as exc:              # FrozenInstanceError is an AttributeError
    print(type(exc).__name__)              # FrozenInstanceError

try:
    order.with_line(OrderLine("ink", 0, Decimal("5")))
except ValueError as exc:
    print(exc)                             # quantity must be positive for ink

print(json.dumps(asdict(paid), default=str)[:70] + "...")
```

Because the orders are immutable, one request handler can never alter an order that another part of the program is still using. State changes are explicit: `with_status` returns a new object. Validation lives in `__post_init__`, so there is no way to construct an invalid line, including through `replace`. `Decimal(str(...))` converts the float `12.99` through its string form, so the exact decimal value the client meant is kept.

## Common Mistakes

- Using a list, dictionary, or set as a default value instead of `default_factory`.
- Assuming type hints are enforced at runtime.
- Defining `__eq__` on a mutable dataclass and then using it as a dictionary key.
- Putting fields without defaults after fields with defaults.
- Mutating a frozen dataclass's nested mutable fields (a list inside a frozen dataclass can still be changed). Use tuples for immutable collections.
- Using a dataclass for something with complex behaviour and identity, where a regular class is clearer.
- Forgetting `repr=False` on sensitive fields.

## Summary

`@dataclass` turns annotated fields into a class with `__init__`, `__repr__`, and `__eq__` generated automatically. Use `field(default_factory=...)` for mutable defaults, `frozen=True` for immutability, `slots=True` for compactness, `kw_only=True` for readable construction, and `__post_init__` for validation. `replace`, `asdict`, and `fields` handle copying and conversion. Dataclasses organize data, but they do not validate input, so check data where it enters your system.
