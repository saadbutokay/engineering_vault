# 6.2 Method Types

## Overview

A class can contain four kinds of methods, each with a different relationship to the class and its instances: instance methods, class methods, static methods, and properties. Choosing the right kind makes the intent of code clear and avoids awkward workarounds.

## Instance Methods

The default kind. The first parameter is `self`, the instance. They read and change that instance's data.

```python
class Account:
    def __init__(self, balance):
        self.balance = balance

    def deposit(self, amount):          # instance method
        self.balance += amount
```

## Class Methods

A class method receives the class itself as its first parameter, conventionally named `cls`, and is declared with `@classmethod`. It works with the class rather than with any one instance. Their most important use is alternative constructors: extra ways to create an object.

```python
class Date:
    def __init__(self, year, month, day):
        self.year = year
        self.month = month
        self.day = day

    @classmethod
    def from_string(cls, text):
        year, month, day = (int(part) for part in text.split("-"))
        return cls(year, month, day)       # cls, not Date, so subclasses work too

    @classmethod
    def today(cls):
        import datetime
        d = datetime.date.today()
        return cls(d.year, d.month, d.day)


d = Date.from_string("2026-03-01")
print(d.year, d.month, d.day)               # 2026 3 1
```

Using `cls(...)` instead of the class name means that if a subclass calls `from_string`, it gets an instance of the subclass.

## Static Methods

A static method receives neither the instance nor the class. It is declared with `@staticmethod`. It is an ordinary function that happens to live inside the class because it is logically related.

```python
class Temperature:
    @staticmethod
    def celsius_to_fahrenheit(celsius):
        return celsius * 9 / 5 + 32


print(Temperature.celsius_to_fahrenheit(100))    # 212.0
```

If a static method does not need anything from the class at all, a plain module-level function is often simpler. Use a static method when grouping it with the class genuinely helps readers find it.

Summary of the three:

| Kind | First parameter | Can access instance data | Can access class data | Typical use |
| --- | --- | --- | --- | --- |
| Instance method | `self` | yes | yes (through `self`) | behaviour of one object |
| Class method | `cls` | no | yes | alternative constructors, class-level operations |
| Static method | none | no | no | related helper function |

## Properties

A property makes a method look like an attribute. Callers write `obj.full_name` with no parentheses, while the class can compute or validate the value behind the scenes.

### Computed Property

```python
class Person:
    def __init__(self, first, last):
        self.first = first
        self.last = last

    @property
    def full_name(self):
        return f"{self.first} {self.last}"


p = Person("Amina", "Rahman")
print(p.full_name)            # Amina Rahman
p.first = "Ayesha"
print(p.full_name)            # Ayesha Rahman, recomputed each time
```

A property without a setter is read-only. `p.full_name = "x"` raises `AttributeError`.

### Setter and Deleter

```python
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius           # goes through the setter

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("below absolute zero")
        self._celsius = value

    @celsius.deleter
    def celsius(self):
        del self._celsius

    @property
    def fahrenheit(self):
        return self._celsius * 9 / 5 + 32


t = Temperature(25)
print(t.fahrenheit)        # 77.0
t.celsius = 30             # runs the setter
t.celsius = -500           # ValueError
```

The real value is stored in `_celsius`. The property named `celsius` controls access to it. Because `__init__` assigns through `self.celsius`, validation also applies when the object is created.

### When to Use a Property

Start with a plain attribute. Python lets you replace it with a property later without changing any calling code, so there is no need to write getter and setter methods in advance, as some other languages require. Use a property when you need:

- validation on assignment
- a value computed from other attributes
- a read-only attribute
- to change how a value is stored without changing the public interface

Keep properties cheap. Callers expect attribute access to be fast and free of side effects, so avoid network calls or heavy work inside one.

## Basic Examples

```python
class Circle:
    PI = 3.14159

    def __init__(self, radius):
        self.radius = radius

    @property
    def diameter(self):
        return self.radius * 2

    @property
    def area(self):
        return self.PI * self.radius ** 2

    @classmethod
    def from_diameter(cls, diameter):
        return cls(diameter / 2)

    @staticmethod
    def is_valid_radius(value):
        return value > 0


c = Circle.from_diameter(10)
print(c.radius, c.diameter)               # 5.0 10.0
print(round(c.area, 2))                   # 78.54
print(Circle.is_valid_radius(-1))         # False
```

## Backend Industry Example

A user model that normalizes and validates its email on every assignment, exposes a computed full name, offers a validation helper as a static method, and builds itself from the dictionary that arrives in a request body.

```python
class User:
    def __init__(self, first_name: str, last_name: str, email: str) -> None:
        self.first_name = first_name
        self.last_name = last_name
        self.email = email                      # runs the setter below

    @property
    def email(self) -> str:
        return self._email

    @email.setter
    def email(self, value: str) -> None:
        cleaned = value.strip().lower()
        if not self.is_valid_email(cleaned):
            raise ValueError(f"invalid email address: {value!r}")
        self._email = cleaned

    @property
    def full_name(self) -> str:
        return f"{self.first_name} {self.last_name}"

    @staticmethod
    def is_valid_email(value: str) -> bool:
        local, _, domain = value.partition("@")
        return bool(local) and "." in domain

    @classmethod
    def from_dict(cls, data: dict) -> "User":
        """Build a user from a request payload, reporting missing fields clearly."""
        try:
            return cls(data["first_name"], data["last_name"], data["email"])
        except KeyError as exc:
            raise ValueError(f"missing field {exc}") from exc


user = User.from_dict(
    {"first_name": "Amina", "last_name": "Rahman", "email": "  Amina@Example.COM "}
)
print(user.email)          # amina@example.com
print(user.full_name)      # Amina Rahman

try:
    user.email = "not-an-email"
except ValueError as exc:
    print(exc)             # invalid email address: 'not-an-email'

print(user.email)          # amina@example.com, the invalid value was rejected
```

No code anywhere can put an unnormalized or invalid email into a `User`, because every path, including construction through `from_dict`, goes through the setter. Callers still write `user.email` as if it were a plain attribute.

## Common Mistakes

- Writing getter and setter methods for every attribute instead of using plain attributes until validation is needed.
- Forgetting that the property and the stored attribute need different names (`email` and `_email`). Using the same name causes infinite recursion.
- Performing slow or side-effecting work inside a property.
- Hard-coding the class name inside a class method instead of using `cls`.
- Using `@staticmethod` for functions that actually need `self` or `cls`.
- Defining the setter before the getter, or giving them different names.

## Summary

Instance methods work on one object through `self`. Class methods receive `cls` and are mainly used as alternative constructors. Static methods are plain functions grouped inside a class. Properties make computed or validated values look like simple attributes, and they let you add validation to an existing attribute without changing how callers use it.
