# 6.8 Enums

## Overview

An enumeration (enum) is a fixed set of named constants. Instead of passing the strings `"pending"`, `"paid"`, and `"shipped"` around and hoping nobody misspells one, you define an `OrderStatus` type with exactly those members. Enums make code self-documenting, catch typos early, and give editors something to autocomplete.

## Defining an Enum

```python
from enum import Enum


class Color(Enum):
    RED = 1
    GREEN = 2
    BLUE = 3
```

Each member has a name and a value.

```python
print(Color.RED)             # Color.RED
print(repr(Color.RED))       # <Color.RED: 1>
print(Color.RED.name)        # RED
print(Color.RED.value)       # 1
```

Look up members in three ways:

```python
print(Color(2))              # Color.GREEN   by value
print(Color["BLUE"])         # Color.BLUE    by name
print(list(Color))           # all members, in definition order
print(len(Color))            # 3
```

An invalid lookup raises `ValueError` (by value) or `KeyError` (by name):

```python
Color(5)                     # ValueError: 5 is not a valid Color
Color["PINK"]                # KeyError: 'PINK'
```

Members are singletons, so compare them with `is` or `==`. They are not equal to their raw values:

```python
print(Color.RED is Color.RED)     # True
print(Color.RED == 1)             # False
```

Members are hashable, so they work as dictionary keys. Enum classes cannot be changed after they are created: you cannot add or reassign members.

## auto()

When the actual values do not matter, `auto()` assigns them.

```python
from enum import Enum, auto


class Direction(Enum):
    NORTH = auto()      # 1
    EAST = auto()       # 2
    SOUTH = auto()      # 3
    WEST = auto()       # 4
```

## IntEnum

`IntEnum` members are also integers. They compare with, and can be used as, ordinary ints.

```python
from enum import IntEnum


class Priority(IntEnum):
    LOW = 1
    MEDIUM = 2
    HIGH = 3


print(Priority.HIGH > Priority.LOW)           # True
print(Priority.LOW == 1)                      # True
print(sorted([Priority.HIGH, Priority.LOW]))  # [<Priority.LOW: 1>, <Priority.HIGH: 3>]
```

This is useful when ordering matters or when you interoperate with code that expects integers, such as protocols. The price is lost type safety, because `Priority.LOW == 1` and `Priority.LOW == Weekday.MONDAY` can be true by accident. Prefer plain `Enum` unless you need the integer behaviour.

## StrEnum

`StrEnum` (Python 3.11 and newer) members are also strings. They compare equal to their string values and can be used wherever a string is expected, including in JSON.

```python
from enum import StrEnum, auto


class Status(StrEnum):
    PENDING = auto()       # 'pending', auto() uses the lower-cased member name
    PAID = auto()
    SHIPPED = "shipped"


print(Status.PAID)                  # paid
print(Status.PAID == "paid")        # True
print(f"status={Status.SHIPPED}")   # status=shipped
```

`StrEnum` is a natural choice for values that come from or go to JSON, URLs, databases, and APIs.

## Flag

`Flag` members can be combined with the bitwise operators to represent sets of options.

```python
from enum import Flag, auto


class Permission(Flag):
    NONE = 0
    READ = auto()          # 1
    WRITE = auto()         # 2
    DELETE = auto()        # 4
    ADMIN = READ | WRITE | DELETE


user = Permission.READ | Permission.WRITE
print(user)                                # Permission.READ|WRITE
print(Permission.READ in user)             # True
print(Permission.DELETE in user)           # False
print(user & Permission.WRITE)             # Permission.WRITE
user |= Permission.DELETE                  # add a flag
print(user == Permission.ADMIN)            # True
user &= ~Permission.WRITE                  # remove a flag
```

`IntFlag` does the same but is also an integer. Use `Flag` unless you need integer interoperability.

## Methods and Extra Behaviour

Enums are classes, so they can have methods and properties.

```python
class Planet(Enum):
    MERCURY = "mercury"
    EARTH = "earth"

    @property
    def label(self):
        return self.value.title()

    @classmethod
    def from_text(cls, text):
        return cls(text.strip().lower())


print(Planet.EARTH.label)               # Earth
print(Planet.from_text("  MERCURY "))   # Planet.MERCURY
```

## Enums with match

```python
def describe(color):
    match color:
        case Color.RED:
            return "stop"
        case Color.GREEN:
            return "go"
        case _:
            return "unknown"
```

## Unique Values and Aliases

Two names with the same value make the second an alias of the first. Add `@unique` to make that an error when it is a mistake.

```python
from enum import Enum, unique


@unique
class Level(Enum):
    LOW = 1
    HIGH = 2
    TOP = 2        # ValueError: duplicate values found in Level: TOP -> HIGH
```

## Basic Examples

```python
from enum import Enum


class Weekday(Enum):
    MONDAY = 1
    TUESDAY = 2
    SATURDAY = 6
    SUNDAY = 7

    def is_weekend(self):
        return self in (Weekday.SATURDAY, Weekday.SUNDAY)


for day in Weekday:
    print(day.name, day.value, day.is_weekend())
```

## Backend Industry Example

An order status that encodes which transitions are legal, a permission set built from flags, and a parser that turns untrusted text into a status with a helpful error.

```python
from enum import Flag, StrEnum, auto


class OrderStatus(StrEnum):
    PENDING = auto()
    PAID = auto()
    SHIPPED = auto()
    CANCELLED = auto()

    def can_transition_to(self, new_status: "OrderStatus") -> bool:
        return new_status in _ALLOWED_TRANSITIONS[self]


_ALLOWED_TRANSITIONS = {
    OrderStatus.PENDING: {OrderStatus.PAID, OrderStatus.CANCELLED},
    OrderStatus.PAID: {OrderStatus.SHIPPED, OrderStatus.CANCELLED},
    OrderStatus.SHIPPED: set(),
    OrderStatus.CANCELLED: set(),
}


def parse_status(raw: str) -> OrderStatus:
    """Convert text from a request into an OrderStatus or explain the problem."""
    try:
        return OrderStatus(raw.strip().lower())
    except ValueError:
        valid = ", ".join(status.value for status in OrderStatus)
        raise ValueError(f"invalid status {raw!r}, expected one of: {valid}") from None


def change_status(current: OrderStatus, requested: str) -> OrderStatus:
    """Validate and apply a status change."""
    new_status = parse_status(requested)
    if not current.can_transition_to(new_status):
        raise ValueError(f"cannot change order from {current} to {new_status}")
    return new_status


class Permission(Flag):
    NONE = 0
    READ = auto()
    WRITE = auto()
    DELETE = auto()
    ADMIN = READ | WRITE | DELETE


def permissions_from_names(names: list[str]) -> Permission:
    granted = Permission.NONE
    for name in names:
        granted |= Permission[name.upper()]      # KeyError for unknown names
    return granted


def is_allowed(granted: Permission, required: Permission) -> bool:
    return required in granted


status = OrderStatus.PENDING
status = change_status(status, " PAID ")
print(status)                                   # paid

for attempt in ("shipped", "pending", "teleported"):
    try:
        status = change_status(status, attempt)
        print("now", status)
    except ValueError as exc:
        print(exc)
# now shipped
# cannot change order from shipped to pending
# invalid status 'teleported', expected one of: pending, paid, shipped, cancelled

editor = permissions_from_names(["read", "write"])
print(is_allowed(editor, Permission.WRITE))     # True
print(is_allowed(editor, Permission.DELETE))    # False

import json
print(json.dumps({"status": OrderStatus.PAID}))     # {"status": "paid"}
```

The transition table is the single source of truth about the order lifecycle. Code elsewhere calls `can_transition_to` and never repeats the rules. A `StrEnum` serializes straight to JSON and compares equal to its string, so it fits easily into APIs and databases. Because statuses are enum members, a typo such as `OrderStatus.SHIPED` fails immediately with an `AttributeError`, instead of silently being a new string.

## Common Mistakes

- Comparing an enum member to its raw value (`Color.RED == 1`), which is `False` for a plain `Enum`.
- Using an `IntEnum` everywhere out of habit and losing type safety.
- Passing strings around instead of enum members, and repeating the valid values in many places.
- Forgetting `@unique` and creating an accidental alias.
- Using mutable values as members' values.
- Building state machines with long `if` chains instead of a transition table.
- Using plain integers or strings as permission flags instead of `Flag`.

## Summary

Enums define a closed set of named values. Use `Enum` for general constants, `StrEnum` for values that live in JSON and databases, `IntEnum` when integer behaviour is needed, and `Flag` for combinable options. Look up members by value or name, use `auto()` when the values do not matter, add methods to attach behaviour, and parse untrusted text into members at the boundary of your system.
